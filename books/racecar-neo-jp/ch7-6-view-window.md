7-5 では、いちばん遠い点が車の後ろにあることがあり、車が大きく曲がろうとして壁にぶつかりました。この回では、**見る範囲を正面 ±90° にしぼり**、さらに「測れなかった 0.0」と「遠すぎる値」を、ある距離にそろえます。この2つは、この先 7-10 まで使い続ける、下ごしらえです。

## ① この回でできるようになること

1. LIDAR のデータから、正面 ±90° の点だけを、左から右の順に取り出せる
2. 0.0（測れなかった点）と、遠すぎる値を、決まった距離にそろえる理由を説明できる
3. 見る範囲をしぼっても、まだ角にぶつかる理由を説明できる

## ③ 本文

### 後ろのほうが遠い通路

図1の左は、長さ 1400 cm のまっすぐな通路です。車はスタートから上を向いていて、前は 500 cm、後ろは 900 cm 先まで何もありません。

7-5 の `farthest_point.py` を走らせると、いちばん遠い点は真後ろにあります。車は大きく右へ曲がろうとして、すぐに右の壁にぶつかりました（灰色）。**車はその場で後ろを向けない**ので、後ろにある空きは、あっても使えないのです。

そこで、正面から左右 90° まで（正面 ±90°）の点だけを見ることにします。こうすると、車は通路にそって、まっすぐ走りました（オレンジ）。

### 0.0 と遠すぎる値をそろえる

図1の右は、7-7 で使う、障害物のある通路（コース B）のスタートで、正面 ±90° を見たものです。

- 正面の −4.5°〜+3.0° の 16 点は、0.0 でした（赤いばつ）。この通路は、正面がずっと先まで開いていて、LIDAR が測れる距離より遠いからです。0.0 のままだと「すぐ目の前に物がある」と読めてしまいます。そこで、0.0 は**遠くまで何もない**とみなし、大きな値に直します
- 残りの点には、正面の近くに 870 cm という遠い値や、左の −15° あたりの 330 cm の値があります。でも、車が今決めたいのは「すぐ先の、どちらへ進めるか」です。何 m も先の違いは、今のハンドルには関係ありません。そこで、`MAX_RANGE`（300 cm）より遠い値は、すべて 300 cm にそろえます（オレンジの線）

こうすると、正面のあたりは 300 cm の平らな所になり、「ここから先は、どこも同じくらい空いている」と読めます。

### 前だけを見て、いちばん遠い点へ

この下ごしらえは、7-10 までずっと使うので、`gaps.py` というファイルに関数 `front_view()` として書いておきます。

```python:gaps.py（はじめの部分）
"""
gaps.py
LIDAR のデータから「空き」（車が進めそうな向きのまとまり）を見つけるための関数（第7章）。
7-6 から 7-10 で、1つずつ足していく。
"""

import math

import numpy as np

HALF_VIEW = 90        # 正面から左右それぞれ何度までを見るか
MAX_RANGE = 300.0     # これより遠い値と、0.0（測れなかった）は、この値にそろえる（cm）


def front_view(scan):
    """正面 ±HALF_VIEW° の点を、左はしから右はしの順に並べて、(角度, 距離) の配列で返す。
    角度は度で、正面が 0、右が＋、左が－。"""
    step = 360 / len(scan)                     # となりの点との角度（0.5°）
    k = int(HALF_VIEW / step)
    offsets = np.arange(-k, k + 1)             # -180 … 180（点の番号の、正面からのずれ）
    angles = offsets * step
    dists = scan[offsets % len(scan)].astype(float)
    dists[dists == 0] = MAX_RANGE              # 測れなかった所は、遠くまで何もないとみなす
    dists = np.minimum(dists, MAX_RANGE)       # 遠すぎる値は、MAX_RANGE にそろえる
    return angles, dists

```

`front_view()` は、角度と距離の2つの配列を返します。どちらも、**左はし（−90°）から右はし（+90°）の順**に並んでいます。LIDAR のデータは正面から時計回りなので、左側の点は配列の後ろのほうにあります。`offsets % len(scan)` で、−180（左はし）を 540 番、…、−1 を 719 番、0 を 0 番、…と、正しい番号に直しています（`%` は、割り算のあまりを求める記号です）。

これを使って、7-5 のプログラムを直します。

```python:farthest_front.py
"""
farthest_front.py
正面 ±90° だけを見て、遠すぎる値をそろえてから、いちばん遠い点の向きへハンドルを切る（7-6）。
gaps.py を同じフォルダに置いて使う。
"""

import sys

import numpy as np

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils
from gaps import front_view

rc = racecar_core.create_racecar()

SPEED = 0.5          # 走る速さ（一定）
FULL_TURN = 30.0     # 目標の向きがこの角度（度）より横にあったら、ハンドルをいっぱいに切る

target = 0.0


def start():
    rc.drive.stop()
    print(">> 正面 ±90° の中で、いちばん遠い点の向きへ走ります")


def update():
    global target
    angles, dists = front_view(rc.lidar.get_samples())
    best = np.flatnonzero(dists == dists.max())          # いちばん遠い点（同じ距離の点が、いくつもあることがある）
    i = best[np.argmin(np.abs(angles[best]))]            # その中で、いちばん正面に近い点
    target = angles[i]
    angle = rc_utils.clamp(target / FULL_TURN, -1.0, 1.0)
    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    print(f"目標の向き {target:+6.1f}°")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

300 cm にそろえたので、いちばん遠い点（300 cm）は、たいていいくつもあります。そこで、その中で**いちばん正面に近い点**を選びます。`np.flatnonzero()` は、条件に合う番号を、すべて配列で返す関数です。

## ④ 数式・コード

### そろえる、という計算

そろえた距離 $d'$ は、LIDAR の値 $d$ から、次のように決まります。

$$
d' = \begin{cases} \text{MAX\_RANGE} & (d = 0) \\ \min(d,\ \text{MAX\_RANGE}) & (d > 0) \end{cases}
$$

プログラムでは、`dists[dists == 0] = MAX_RANGE` と `np.minimum(dists, MAX_RANGE)` の2行です。`np.minimum()` は、2つの値のうち小さいほうを、配列の点ごとに選びます。

### 点の数

正面 ±90° は、0.5° ずつなので、$90 \div 0.5 \times 2 + 1 = 361$ 点です（正面の 1 点をふくむ）。

## ⑤ つまずきポイント

### 0.0 を「近い」と読んでしまう

5-3 で見たように、LIDAR は測れなかった所を 0.0 にします。7-1 で前の物までの距離を求めたときは、0.0 を入れないようにしました。空きを探すときは反対に、0.0 を「遠い」に直します。同じ 0.0 でも、何を探すかで扱いがちがうことに気をつけましょう。

### MAX_RANGE を大きくしすぎる

`MAX_RANGE` を 1000 cm にすると、LIDAR の値がほとんどそのまま使われ、ばらつきで遠い点があちこちに飛びます（7-5 の⑤）。小さくしすぎると、今度はせまい所の奥まで見えず、どこも「300 cm も空いていない」になります。まずは 300 cm から始め、7-7 以降のしきい値（空きとみなす距離）より大きくしておきます。

## ⑥ 確認問題

**問1**　`front_view()` が返す配列の、0 番の点と、180 番の点は、それぞれ何度の向きですか。

:::details 答え
0 番は左はしの −90°、180 番は正面の 0° です（361 点のうち、真ん中）。
:::

**問2**　ある向きの LIDAR の値が 0.0 でした。`front_view()` のあと、その向きの距離はいくつになりますか。それはなぜですか。

:::details 答え
300 cm（`MAX_RANGE`）です。0.0 は、遠すぎて測れなかったことを表すので、遠くまで何もないとみなします。
:::
