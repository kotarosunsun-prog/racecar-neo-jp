## ③ 本文

### 壁沿い走行とは

6-2 のライントレースでは、床の線が「進む道」を教えてくれました。でも、ふつうの廊下やトンネルには、線はありません。そのかわりに、左右に**壁**があります。LIDAR で壁までの距離を測り、その距離を保つようにハンドルを切れば、線がなくても、壁にそって走れます。これが**壁沿い走行**です。

0-1 で紹介したように、RACECAR の始まりは、MIT の地下トンネルでのレースでした。トンネルを速く、ぶつからずに走るための基本の技が、壁沿い走行です。第7章の安全停止や、そのあとのグランプリでも、この回からの考え方を使います。

### Lab I の課題

課題のファイルは、labs フォルダの中の `lab_i/lab_i.py` です。原典の Purpose と Expected Outcome を訳すと、次のとおりです。

> このプログラムは、RACECAR が自動で壁にそって走れるようにするものです。右の壁、左の壁、両側の壁のどれにも対応でき、とても狭い通路にも、とても広い通路にも対応できる柔軟さが必要です。

- LIDAR で、ある距離・ある角度にある壁を見つける
- 理想は、壁から決まった距離を保って走ること。両側に壁が見えるときは、2つの壁の真ん中を走る
- 右の壁だけ見える、左の壁だけ見える、両側に見える、で、違う「状態」をもってよい
- speed と angle は、毎コマ計算し直す。そして、`update()` の**最後に1回だけ**車に送る

原典には「ここまで来たあなたには、ここからは手助けを少なくします」とも書かれています。実際に、Lab I のひな形には `start()`・`update()`・`update_slow()` の枠しかありません。この本では、6-5 から少しずつ部品を作り、組み立てていきます。

:::message alert
**訳注：ひな形の食い違い**
Lab I のひな形では、ライブラリの場所を `sys.path.insert(0, '../library')` と書いています。ほかの課題は `sys.path.insert(1, "../../library")` で、ひな形のコメントにも「フォルダの中に入れたファイルなら `../../library`」とあります。公式のインストーラで入れた場合は、ライブラリの場所があらかじめ Python に登録されるので、どちらのままでも動きます。ファイルを別の場所で動かすときは、`"../../library"` に直しましょう。
また、ひな形には `import racecar_utils as rc_utils` がありません。LIDAR の関数を使うので、`import racecar_core` の下に足してください。
:::

### シミュレータのレベル

シミュレータのレベルは、**Neo Labs** の **Lab I: Wall Follower** です。最初の画面で、次の3つのモードを選べます。

| モード | できること |
|---|---|
| Exploration（探索） | 自由に走らせて練習する。Tab キーで、次のチェックポイント（全部で4つ）へ進める |
| Autograder（自動採点） | 下の表のコースを順番に走り、点数をつける |
| Race（レース） | スタートからゴールまでの時間を測る。ひな形には「いちばん速い時間が勝ち！」とある |

どのモードでも、壁（Posts のコースでは柱）にふれると、そこで失敗になります。

自動採点のコースは、次の6つです。コースの形は、探索モードで実際に見て確かめましょう。

| 順番 | コース | 課題 | 点数 | 制限時間 |
|---|---|---|---|---|
| 1 | 45 Degree | 壁にふれずに走りきる | 2 | 12秒 |
| 2 | 90 Degree | 壁にふれずに走りきる | 3 | 20秒 |
| 3 | Tight | 壁にふれずに走りきる | 3 | 30秒 |
| 4 | Posts | 柱にふれずに走りきる | 2 | 30秒 |
| 5 | Full Course | 壁にふれずに走りきる | 5 | 90秒 |
| 6 | Challenge: Organic | コースを走りきる | 5 | 90秒 |

Full Course と Challenge: Organic には、走りきったときの時間で点数が増減する**タイムボーナス**があります。

- Full Course：20秒以内 +1、30秒以内 +0.5、45秒以内 ±0、60秒以内 −1、それより遅い −2
- Challenge: Organic：45秒以内 +0.5、60秒以内 ±0、それより遅い −0.5

:::message
この本では、ゲインなどの数値を、説明用の簡単なモデルに合わせて決めています。シミュレータのコースを走りきるための数値は載せません。考え方と調整のしかたを身につけて、自分の車で合わせましょう。
:::

### 毎コマくり返すこと

壁沿い走行のプログラムは、`update()` の中で、次の4つを毎コマくり返します。

![左は、上から見た壁沿い走行。右に壁があり、壁から 50 cm のところに緑の点線で目標の線が引いてある。車は目標の線より壁から遠いところを前へ進んでいて、LIDAR で測った壁までの距離 d と、ずれ（d − 50）が矢印で示されている。右は、update() の中で毎コマくり返すことを、上から順に並べた図。① 測る（LIDAR で右の壁までの距離 d を求める、6-5・6-6）、② 比べる（ずれ = d − 目標の距離、6-7）、③ 決める（ずれとその変わり方から angle を決める、6-7・6-9・6-10）、④ 送る（rc.drive.set_speed_angle を update の最後に1回だけ）。④ から ① へ矢印がもどり、車が動くと距離が変わるので、次のコマでまた測ることを表している。下に、⑤ 調べる：記録をとってグラフにし、走り方を確かめる（6-8）とある](/images/racecar-neo-jp/6-4/fig1-overview.png)
*図1　壁沿い走行で、毎コマくり返すこと*

1. **測る**：LIDAR で、壁までの距離を求める（6-5・6-6）
2. **比べる**：目標の距離とのずれを求める（6-7）
3. **決める**：ずれから、ハンドルの角度を決める（6-7・6-9・6-10）
4. **送る**：`rc.drive.set_speed_angle()` を、最後に1回だけ呼ぶ

これは、6-1 のフィードバック制御の形そのものです。6-5 から 6-10 までは、まず**右の壁**だけにそって走るプログラムを作ります。左の壁や両側の壁、壁が見えないときの切りかえは、6-11 からあとで扱います。

### やってみよう：右の壁までの距離を表示しながら走る

まずは、ハンドルは動かさずに、まっすぐ走りながら、右の壁までの距離を表示してみます。`update()` の中を、「測る」「決める」「送る」の順に書いておきます。

```python:wall_probe.py
"""
wall_probe.py
まっすぐ走りながら、右の壁までの距離を表示する（壁沿い走行の準備）。
ハンドルはまだ動かさない。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

SPEED = 0.3      # 走る速さ

right = 0.0      # 右の壁までの距離（update_slow で表示する）


def start():
    rc.drive.stop()
    print(">> まっすぐ走りながら、右の壁までの距離を表示します")


def update():
    global right

    # 1. 測る：右（90°）の距離
    scan = rc.lidar.get_samples()
    right = rc_utils.get_lidar_average_distance(scan, 90)

    # 2. 決める：速さと角度（角度は、まだ 0 のまま）
    speed = SPEED
    angle = 0.0

    # 3. 送る：update() の最後に1回だけ
    rc.drive.set_speed_angle(speed, angle)


def update_slow():
    print(f"右の壁まで {right:6.1f} cm")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

説明用の簡単なモデルで、幅 150 cm の廊下の真ん中から、少しだけ（3°）右を向いて走らせると、1秒ごとに次のように表示されました。

```text
>> まっすぐ走りながら、右の壁までの距離を表示します

右の壁まで   74.2 cm
右の壁まで   72.2 cm
右の壁まで   68.5 cm
右の壁まで   66.3 cm
右の壁まで   63.6 cm
右の壁まで   61.6 cm
右の壁まで   60.2 cm
右の壁まで   57.1 cm
右の壁まで   54.6 cm
右の壁まで   52.4 cm
右の壁まで   49.4 cm
```

たった 3° の傾きでも、12秒で 25 cm 以上、壁に近づいています。ハンドルをまっすぐにしておくだけでは、壁沿いには走れません。測った距離を使って、ハンドルを切る必要があります。

シミュレータでも、Lab I のレベルで動かしてみましょう。壁までの距離が、どれくらいの数で、どう変わるかを見ておくと、このあとの回がわかりやすくなります。

## ④ 数式・コード

### 右と左の角度

LIDAR の角度は、正面が 0° で、時計回りに増えます（5-3）。右の壁を見るときは 90°、左の壁を見るときは 270° を使います。

```python
right = rc_utils.get_lidar_average_distance(scan, 90)    # 右
left = rc_utils.get_lidar_average_distance(scan, 270)    # 左
```

両側の壁の真ん中を走りたいときは、`right - left` が 0 になるようにすればよい、という考え方ができます。これは 6-11 からあとで扱います。

### 送るのは最後に1回だけ

`set_speed_angle()` を `update()` の途中で何回も呼ぶと、最後に呼んだものだけが使われます。途中で呼ぶと、あとから書いた処理とぶつかって、思わぬ動きになりがちです。Lab I の Expected Outcome のとおり、speed と angle は変数で計算しておき、最後に1回だけ送る形にしておきましょう。

## ⑤ つまずきポイント

### `racecar_utils` が見つからない、と言われる

`NameError: name 'rc_utils' is not defined` と出たら、`import racecar_utils as rc_utils` を書き忘れています。Lab I のひな形には入っていないので、自分で足します。

### 距離が 0.0 と表示される

`get_lidar_average_distance()` は、調べた範囲にデータ（0.0 でない値）が1つもないと、0.0 を返します（5-3）。シミュレータの LIDAR は、近すぎる物（12 cm より近い）や、遠すぎる物（10 m より遠い）を 0.0 にします。まわりに壁がない場所では、0.0 になることがあります。

### 走り出したとたんに壁にぶつかる

このプログラムは、ハンドルを動かしません。車の向きが少しでも壁のほうを向いていれば、いつかはぶつかります。シミュレータで試すときは、ぶつかる前に Backspace キーで止めましょう（1-2）。

## ⑥ 確認問題

**問1**　Lab I の Expected Outcome で、speed と angle は「いつ、何回」車に送ることになっていますか。

:::details 答え
毎コマ計算し直して、`update()` の最後に1回だけ送ります。
:::

**問2**　左の壁までの距離を、`get_lidar_average_distance()` で求めるには、角度に何を入れますか。

:::details 答え
270 です。LIDAR の角度は正面が 0° で時計回りに増えるので、左は 270° です。
:::

**問3**　Full Course を、壁にふれずに 25秒で走りきりました。タイムボーナスは何点ですか。

:::details 答え
+0.5 点です。20秒をこえ、30秒以内なので +0.5 になります。
:::
