この回から 7-11 までは、LIDAR で車のまわりを見て、**いちばん空いている方向**へ走る方法を作っていきます。壁沿い走行とちがって、壁がなくても、障害物があっても走れる方法です。英語では Gap Follower（すき間をたどるもの）とよばれます。まずは、いちばんかんたんな考え方、「いちばん遠い点の向きへ走る」から始めて、何が困るのかを確かめます。

## ① この回でできるようになること

1. LIDAR のいちばん遠い点の向きを求められる
2. 目標の向きに比例して、ハンドルを切れる
3. 「いちばん遠い点へ向かう」だけでは、曲がり角の角にぶつかる理由を説明できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Gap Follower | ギャップフォロワー | LIDAR で空いている方向を探して、そこへ向かう走り方 |
| Farthest point | いちばん遠い点 | LIDAR の点のうち、距離がいちばん大きい点 |

| Corner | 角（かど） | 壁の曲がり目の、つき出ている所 |

## ③ 本文

### いちばん遠い点へ向かう

遠くまで何もない向きは、しばらく進んでもぶつからない向きです。そこで、LIDAR の 720 点の中で、いちばん遠い点を探し、その向きへハンドルを切ります。

- いちばん遠い点の番号は `np.argmax(scan)` で求められます。`np.argmax()` は、配列の中でいちばん大きい値の番号を返す NumPy の関数です。0.0（測れなかった点）は、いちばん小さい値なので、選ばれません
- 番号 $i$ の点の角度は $i \times 0.5°$ です。180° より大きい角度は、360° を引いて、左を負（−180°〜180°）にします
- 目標の向きに比例してハンドルを切ります。`FULL_TURN = 30` は、「目標の向きが 30° 以上横なら、ハンドルをいっぱいに切る」という意味です。6-2 のライントレースと同じ、比例制御です

```python:farthest_point.py
"""
farthest_point.py
LIDAR のすべての点（シミュレータでは 720 点）の中で、いちばん遠い点の向きへハンドルを切る（7-5）。
"""

import sys

import numpy as np

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

SPEED = 0.5          # 走る速さ（一定）
FULL_TURN = 30.0     # いちばん遠い点がこの角度（度）より横にあったら、ハンドルをいっぱいに切る

target = 0.0         # いちばん遠い点の角度（度。正面が 0、右が＋、左が－）
far = 0.0            # いちばん遠い点までの距離


def start():
    rc.drive.stop()
    print(">> いちばん遠い点の向きへ走ります")


def update():
    global target, far
    scan = rc.lidar.get_samples()
    i = int(np.argmax(scan))                   # いちばん遠い点の番号（0.0 = 測れなかった点は、選ばれない）
    far = float(scan[i])
    target = i * 360 / len(scan)               # 0〜360°
    if target > 180:
        target -= 360                          # -180〜180° にする（左が－）
    angle = rc_utils.clamp(target / FULL_TURN, -1.0, 1.0)
    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    print(f"いちばん遠い点：{target:+6.1f}° の向き、{far:6.1f} cm")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

### なぜぶつかるのか

図1の右は、ぶつかる 1 秒前の様子です。いちばん遠い点は、左うしろ −146° の向きにありました。その向きの光線は、ななめの通路の入り口の角の**すぐ横をかすめて**、来た道の奥の壁まで届いています。だから遠いのです。車は、その向きへ左にハンドルをいっぱいに切り、すぐ左にあったななめの壁にぶつかりました。

ここから、2つの問題がわかります。

1. **後ろを選んでしまう**：来た道が長いと、うしろのほうが遠く見えます。車はその場では向きを変えられないので、大きく曲がろうとして、横の壁にぶつかります。図1では、まさにこれが起きました
2. **遠い点は、物のはしのすぐ横にある**：光線は太さがないので、角のすぐ横をかすめても遠くまで届きます。でも、車には幅があります。光線が通れるすき間を、車も通れるとは限りません

1 は次の 7-6 で、2 は 7-7〜7-10 で、1つずつ直していきます。

## ④ 数式・コード

### 番号から角度へ

シミュレータの LIDAR の 720 点は、正面から時計回りに 0.5° ずつ並んでいます（実機も同じです）。番号 $i$ の角度 $\theta$ を、左が負になるように直すと、次のようになります。

$$
\theta = \begin{cases} 0.5\,i & (0.5\,i \le 180) \\ 0.5\,i - 360 & (0.5\,i > 180) \end{cases}
$$

プログラムでは、`len(scan)` を使って `i * 360 / len(scan)` と書いています。こうしておくと、点の数がちがう LIDAR（実物の車など）でも、そのまま使えます。

### 比例制御としてのハンドル

$$
\text{angle} = \text{clamp}\left(\frac{\theta}{\text{FULL\_TURN}},\ -1,\ 1\right)
$$

これは、6-2 のライントレースの angle = KP × ずれ と同じ形で、$K_P = 1 / \text{FULL\_TURN}$ です。`FULL_TURN` を小さくすると、少しの向きのずれでも大きくハンドルを切ります。

## ⑤ つまずきポイント

### 目標の向きが、ぱっと飛ぶ

いちばん遠い点は、1 点だけで決まります。遠い点が2か所あって、距離がほぼ同じだと、LIDAR のばらつきで、どちらが選ばれるかが入れかわります。そのたびに、ハンドルが右へ左へ大きく切りかわります。7-7 では、点1つではなく、点の「まとまり」で向きを決めます。

### 何もない所で、あちこち向く

まわりに何もないと、LIDAR の点はすべて 0.0（測れなかった）になり、`np.argmax` は番号 0（正面）を返します。すると正面へ進みますが、それはたまたまです。7-6 で、0.0 の扱いを決めます。

## ⑥ 確認問題

**問1**　いちばん遠い点の番号が 610 でした。角度は何度ですか。`FULL_TURN = 30` なら、angle はいくつですか。

:::details 答え
$610 \times 0.5 = 305°$ で、180° より大きいので $305 - 360 = -55°$（左）です。angle は $-55 \div 30$ を −1〜1 におさめて、−1（左にいっぱい）です。
:::

**問2**　図1で、いちばん遠い点へ引いた線が、角のすぐ横を通っていました。車がその向きへ進むと、なぜぶつかるのでしょうか。

:::details 答え
光線には幅がありませんが、車には幅があります。光線が角のすぐ横をかすめて通れても、車の半分の幅だけ横は、角にぶつかります。
:::
