PID のゲインは、どうやって決めればよいのでしょうか。この回では、2つの方法を学びます。1つは、6-13 の数を見ながら、**手で1つずつ合わせていく**方法です。もう1つは、**限界感度法**（ジーグラー・ニコルスの方法）とよばれる、決まった手順で最初の値を求める方法です。

## ① この回でできるようになること

1. 手でゲインを合わせるときの順番と、気をつけることを説明できる
2. 限界感度法で、限界ゲインと限界周期を見つけられる
3. 限界ゲインと限界周期から、PI のゲインを計算できる
4. 限界感度法で決めた値を、出発点として手で直していける

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Tuning | チューニング（調整） | ゲインなどの数を、よい走りになるように決めること |
| Ultimate gain（Ku） | 限界ゲイン | P だけのとき、揺れが大きくも小さくもならず、同じ大きさで続くようになる KP |
| Ultimate period（Tu） | 限界周期 | そのときの揺れの、1往復の時間 |
| Ziegler–Nichols method | ジーグラー・ニコルスの方法 | Ku と Tu から、PID のゲインを決める計算のしかた。限界感度法ともいう |

## ③ 本文

### 手で合わせる：順番が大事

ゲインを手で合わせるときは、次の順番で進めます。

1. **I と D を 0 にして、P だけで走らせる**。どのくらいの KP で、目標に向かっていくかを見る
2. **D（この本では壁の向き）を足して、行き過ぎをおさえる**
3. **P を大きくして、すばやくする**。行き過ぎがふえたら、D を少し大きくする
4. **最後に I を足して、残ったずれを消す**。I は小さい値から
5. **いくつかの場面で確かめる**（6-13）

合わせるときのコツは、次のとおりです。

- **1回に1つだけ変える**。2つ同時に変えると、どちらが効いたのかわからない
- **2倍・半分のように、大きめに変えてみる**。0.02 を 0.021 にしても、違いがわからない
- **毎回、記録をとって、6-13 の数を表にする**

説明用の簡単なモデルで、この順番に合わせたときの記録です（壁から 100 cm の所から走らせたときの数と、6-11 の丸い部屋で最後に残ったずれ）。

| 手順 | KP | 壁の向き | KI | 結果 |
|---|---|---|---|---|
| 1 | 0.02 | 0 | 0 | 2.3秒で壁にぶつかった（6-7・6-8 の揺れ） |
| 2 | 0.02 | 0.02 | 0 | 行き過ぎ 14.3 cm。ブレーキが弱い |
| 2 | 0.02 | 0.04 | 0 | 行き過ぎ 1.1 cm、立ち上がり 2.35 秒、整定 3.37 秒 |
| 3 | 0.04 | 0.04 | 0 | 行き過ぎ 4.8 cm、立ち上がり 1.17 秒、整定 3.37 秒。すばやくなった |
| 3 | 0.08 | 0.04 | 0 | 行き過ぎ 22.3 cm。大きくしすぎたので、0.04 にもどす |
| 4 | 0.04 | 0.04 | 0.005 | まっすぐな壁はほぼ同じ。丸い部屋のずれが −7.3 cm → −0.4 cm |

最後の行が、6-13 の表の「エ」です。

### 限界感度法：決まった手順で、最初の値を求める

手で合わせる方法は、どんな相手にも使えますが、はじめの値の見当がつかないと、時間がかかります。**限界感度法**は、次の手順で、PID のゲインの最初の値を計算で求める方法です。1942年に、ジーグラーとニコルスが発表しました。

1. I と D を 0 にして、P だけにする
2. KP を少しずつ大きくしながら、わざと揺らしてみる
3. 揺れが小さくならず、**同じ大きさで続く**ようになったときの KP を**限界ゲイン $K_u$**、そのときの1往復の時間を**限界周期 $T_u$** とする
4. 下の表で、ゲインを計算する

| 使う制御 | KP | KI | KD |
|---|---|---|---|
| P | $0.5\,K_u$ | ― | ― |
| PI | $0.45\,K_u$ | $0.54\,K_u / T_u$ | ― |
| PID | $0.6\,K_u$ | $1.2\,K_u / T_u$ | $0.075\,K_u T_u$ |

### 壁沿い走行で使うときの注意

6-8 で見たように、壁沿い走行は、**P だけだと、どんな KP でも揺れが止まりません**。揺れが小さくなっていく KP がないので、手順3の「同じ大きさで続く KP」も決まりません。

そこで、D の役目をしている**壁の向きのゲインを先に決めて（ここでは 0.04）、固定してから**、KP だけを大きくしていきます。壁の向きの部分も含めて「車」とみなし、それに P と I を足す、と考えるのです。D の役目はもう壁の向きが受け持っているので、表の **PI** の行を使います。

### やってみよう：ボタンで KP を変えながら揺らす

走りながら、ボタンで KP を変え、わざと揺らして、揺れの大きさと周期を表示するプログラムです。

```python:wall_follow_tune.py
"""
wall_follow_tune.py
KP をボタンで変えながら壁にそって走り、揺れの大きさと周期を表示する（6-14 の限界感度法の準備）。
Y ボタン：KP を 1.2 倍にする　X ボタン：KP を 1/1.2 倍にする
A ボタン：0.3 秒だけハンドルを右にいっぱいに切って、わざと揺らす
（壁の向きのゲイン KA は固定。I は使わない）
"""

import sys
import math

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

TARGET = 50.0     # 右の壁から保ちたい距離（cm）
SPEED = 0.5       # 走る速さ（一定）
KA = 0.04         # 壁の向き（1°あたり）に対するゲイン（固定）
THETA = 30        # 2本の光線の間の角度（度）
SIDE = 1.0        # ずれがこれより大きく反対側に行ったら「目標をまたいだ」と数える（cm）

KP = 0.1          # ボタンで変える
kick = 0.0        # わざと揺らす残り時間（秒）
t = 0.0           # 走り始めてからの時間（秒）
side = 0          # 今、目標のどちら側にいるか（＋1：遠い側、－1：近い側）
crossings = []    # 目標をまたいだ時刻
recent = []       # 最近 2 秒の (時刻, ずれ)


def right_wall(scan):
    """右の壁の向き（度）と、壁までの距離（cm）を返す。測れなければ (None, None)（6-10）"""
    a = rc_utils.get_lidar_average_distance(scan, 90 - THETA)
    b = rc_utils.get_lidar_average_distance(scan, 90)
    if a == 0.0 or b == 0.0:
        return None, None
    th = math.radians(THETA)
    alpha = math.atan2(a * math.cos(th) - b, a * math.sin(th))
    return math.degrees(alpha), b * math.cos(alpha)


def start():
    global t, side, kick
    rc.drive.stop()
    t = 0.0
    side = 0
    kick = 0.0
    crossings.clear()
    recent.clear()
    print(">> Y：KP を 1.2 倍、X：KP を 1/1.2 倍、A：わざと揺らす")


def update():
    global KP, t, side, kick

    if rc.controller.was_pressed(rc.controller.Button.Y):
        KP *= 1.2
        crossings.clear()                  # KP を変えたら、周期を測り直す
        print(f"KP を {KP:.3f} にした")
    if rc.controller.was_pressed(rc.controller.Button.X):
        KP /= 1.2
        crossings.clear()
        print(f"KP を {KP:.3f} にした")
    if rc.controller.was_pressed(rc.controller.Button.A):
        kick = 0.3

    t += rc.get_delta_time()
    scan = rc.lidar.get_samples()
    wall_angle, distance = right_wall(scan)

    angle = 0.0
    if distance is not None:
        error = distance - TARGET
        angle = rc_utils.clamp(KP * error + KA * wall_angle, -1.0, 1.0)

        # 揺れの記録：目標を SIDE cm 以上こえて反対側に行ったら、またいだ時刻を残す
        new_side = side
        if error > SIDE:
            new_side = 1
        elif error < -SIDE:
            new_side = -1
        if side != 0 and new_side != side:
            crossings.append(t)
        side = new_side

        recent.append((t, error))
        while recent[0][0] < t - 2.0:
            recent.pop(0)

    if kick > 0:
        angle = 1.0                        # わざと右に切る
        kick -= rc.get_delta_time()

    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    if len(recent) == 0:
        print("壁が見えない")
        return
    amplitude = max(abs(e) for _, e in recent)
    if len(crossings) >= 5:
        period = (crossings[-1] - crossings[-5]) / 2     # 4回またぐ ＝ 2往復
        print(f"KP {KP:.3f}　揺れの大きさ {amplitude:4.1f} cm　周期 {period:.2f} 秒")
    else:
        print(f"KP {KP:.3f}　揺れの大きさ {amplitude:4.1f} cm　周期 （まだ測れない）")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

- **揺れの大きさ**：最近 2 秒の中で、ずれがいちばん大きかった値です
- **周期**：ずれが、目標を 1 cm 以上こえて反対側へ行くたびに、その時刻を記録します。4回またぐと 2往復なので、その時間を 2 でわって、1往復の時間にしています。ばらつきで、目標のまわりを細かく行き来しても数えないように、1 cm の幅（`SIDE`）をつけています

使い方は、A ボタン（キーボードの 1）でわざと揺らし、揺れがだんだん小さくなるかを見ます。小さくなるなら、Y ボタン（キーボードの 4）で KP を 1.2 倍にして、また揺らします。揺れが同じ大きさで続くようになったら、そのときの KP と周期を書きとめます。

![時間と、ずれのグラフ。0〜10 秒は KP 0.100、10〜20 秒は KP 0.120、20〜30 秒は KP 0.144、30〜40 秒は KP 0.173。それぞれの区間のはじめに、A ボタンでわざと揺らしている。KP 0.100 と 0.120 では、揺れは 7 cm から始まって、4〜5 回の往復で 1 cm くらいまで小さくなる。KP 0.144 では、揺れは小さくなるのに時間がかかる。KP 0.173 では、揺れが 6 cm くらいのまま小さくならず、同じ大きさで続いている](/images/racecar-neo-jp/6-14/fig1-find-ku.png)

説明用の簡単なモデルで、10 秒ごとに KP を 1.2 倍にしていったときの記録が図1です。KP が 0.173 になると、揺れが小さくならなくなりました。そのころの表示は、次のとおりです。

ここから、$K_u \approx 0.17$、$T_u \approx 1.8$ 秒とします。PI の行で計算すると、

$$
K_P = 0.45 \times 0.17 \approx 0.077, \qquad K_I = 0.54 \times \frac{0.17}{1.8} \approx 0.051
$$

### 限界感度法の値は、出発点

計算した値で、壁から 100 cm の所から走らせてみました。

|---|---|---|---|---|---|---|
| 限界感度法の PI | 0.077 | 0.051 | 0.83 秒 | 21.3 cm | 7.03 秒 | +0.5 cm |

限界感度法の値は、立ち上がりはいちばん速いものの、21 cm も行き過ぎました。もともと限界感度法は、「揺れが1往復するごとに 1/4 くらいに小さくなる」ような、きびきびした反応をめざす方法です。壁沿い走行のように、行き過ぎると壁にぶつかるものには、強すぎることが多いのです。

でも、**何もわからない所から、数回走らせるだけで、だいたいの大きさがわかる**のは、大きな助けになります。この例でも、限界感度法の値を半分にすると、手で合わせた値にかなり近づきました。限界感度法で出発点を決め、そこから手で合わせていくのが、よい使い方です。

## ④ 数式・コード

### ゲインの大きさの見当

限界ゲイン $K_u$ は、「これより KP を大きくすると、揺れが大きくなっていく」境目です。表の KP は、どれも $K_u$ の半分くらい（0.45〜0.6 倍）になっています。つまり、限界感度法は「揺れが止まらなくなる境目の、半分くらいの強さで使う」という考え方です。

### I の強さと限界周期

PI の $K_I = 0.54\,K_u / T_u$ は、$K_P / K_I = T_u / 1.2$ と書きかえられます。この $K_P / K_I$ は、「I の部分が、P の部分と同じ大きさになるまでに、ずれが続く時間」の目安で、**積分時間**とよばれます。揺れの周期 $T_u$ より少し短い時間で I が効いてくる、という意味です。この例の 1.5 秒は、6-11 で「少しずつ」効かせた値（手で合わせた値の積分時間は $0.04 / 0.005 = 8$ 秒）よりずっと短いので、I が強く、行き過ぎが大きくなりました。

## ⑤ つまずきポイント

### 揺れが同じ大きさになる KP が、ちょうど見つからない

1.2 倍ずつ変えると、「小さくなっていく KP」と「大きくなっていく KP」の間に、ちょうどの値がはさまれることがあります。そのときは、小さいほうの値を $K_u$ として使います（安全なほう）。

### 揺れが大きくなりすぎて、壁にぶつかる

$K_u$ をこえると、揺れはどんどん大きくなります。揺れが大きくなりはじめたら、すぐに X ボタンで KP を下げましょう。シミュレータで試すときも、実物の車で試すときも、ゆっくりの SPEED から始めます。

### 速さを変えたら、ゲインも変わる

$K_u$ と $T_u$ は、走る速さで変わります。速く走ると、同じハンドルでも向きが速く変わるので、$K_u$ は小さく、$T_u$ は短くなります。ゲインは、実際に走らせる速さで決めましょう（6-19）。

## ⑥ 確認問題

**問1**　$K_u = 0.2$、$T_u = 2.0$ 秒でした。PI のゲインを限界感度法で求めましょう。

:::details 答え
$K_P = 0.45 \times 0.2 = 0.09$、$K_I = 0.54 \times 0.2 \div 2.0 = 0.054$ です。
:::

**問2**　手でゲインを合わせるとき、KP と KI を同時に変えないほうがよいのはなぜですか。

:::details 答え
走りが変わったとき、どちらを変えたせいなのかが、わからなくなるからです。
:::

**問3**　壁沿い走行で、P だけのまま限界感度法を使えないのはなぜですか。

:::details 答え
P だけだと、どんな KP でも揺れが止まらないので、「揺れが同じ大きさで続く境目」が決まらないからです。壁の向きのゲインを先に決めて固定してから、KP を大きくしていきます。
:::
