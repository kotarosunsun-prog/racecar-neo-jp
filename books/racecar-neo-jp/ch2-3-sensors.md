2-1・2-2 では、コントローラの状態をポーリングで読みました。RACECAR のセンサも、まったく同じように**毎コマこちらから値を聞きにいく**ことで読めます。この回では、カメラ・LIDAR・IMU から値を取り出し、それぞれがどんなデータを返すのかを確かめます。

## ① この回でできるようになること

1. RACECAR の3つのセンサから、プログラムで値を取り出せる
2. 返ってくるデータの形（数の並び方）と単位を説明できる
3. シミュレータと実機で違うところを知っておく

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Array | 配列 | 数をたくさん並べてまとめたもの |
| Index | インデックス（番号） | 配列の何番目かを表す数。0から数える |
| Shape | 形 | 配列が「何行・何列・何枚」でできているか |
| Pixel | 画素（ピクセル） | 画像を作っている、1つ1つの小さな点 |
| Depth image | 深度画像 | 各画素に、色ではなく「そこまでの距離」が入った画像 |
| Sample | サンプル | LIDAR が1周のうちに測った、1つ1つの距離 |
| Linear acceleration | 加速度 | 速さがどれだけ変わっているか |
| Angular velocity | 角速度 | どれだけの速さで回っているか |

## ③ 本文

### センサの読み方は、どれも同じ形

センサの値は、`rc.センサの名前.命令()` の形で取り出します。コントローラと同じく、呼ぶたびにそのコマの最新の値が返ってきます。

```python
image = rc.camera.get_color_image()          # カメラのカラー画像
scan = rc.lidar.get_samples()                # LIDAR の1周分の距離
accel = rc.physics.get_linear_acceleration() # IMU の加速度
```

### センサの一覧

| センサ | 命令 | 返ってくるもの | 形 | 単位 |
|---|---|---|---|---|
| カメラ | `rc.camera.get_color_image()` | カラー画像 | 480行 × 640列 × 3色 | 0〜255 の明るさ |
| カメラ | `rc.camera.get_depth_image()` | 深度画像 | 480行 × 640列 | cm |
| LIDAR | `rc.lidar.get_samples()` | まわり1周の距離 | 720個の小数の配列 | cm |
| IMU | `rc.physics.get_linear_acceleration()` | 加速度 | 3個（3つの軸） | m/s² |
| IMU | `rc.physics.get_angular_velocity()` | 角速度 | 3個（3つの軸） | rad/s |

それぞれのセンサを、もう少し詳しく見ていきます。

### カメラ：数の「表」としての画像

カメラの画像は、縦480個 × 横640個の点（画素）が並んだものです。1つの画素には、**青・緑・赤**の3つの明るさが 0〜255 の数で入っています。ふつうの「赤・緑・青（RGB）」とは**逆の順番**なので注意しましょう。

```python
image = rc.camera.get_color_image()
print(image.shape)         # (480, 640, 3)
print(image[240][320])     # 画面のまん中の画素の [青, 緑, 赤]
```

`image[行][列]` で、上から何行目・左から何列目の画素かを指定します。どちらも0から数えます。

**深度画像**は、同じ480 × 640 の並びの各画素に、色の代わりに**その点までの距離**（cm）が入っています。カメラの画像を使って信号の色を見分ける方法は、第5章で学びます。

### LIDAR：まわり1周の距離の並び

LIDAR は、回転しながらレーザーを出して、まわり360°の壁や物までの距離を測ります。`get_samples()` が返すのは、その距離を**真正面から時計回りに**並べたものです。

- 距離は **720個の小数（float）の配列**で返ってきます。シミュレータでも実機でも同じ形です
- 点と点の間の角度は、360° ÷ 720 = **0.5°** です
- 番号0が真正面、番号180（90°）が右、番号360（180°）が真後ろ、番号540（270°）が左です
- 距離の単位は **cm** です
- **0.0** は「測れなかった」という意味です。遠すぎる、ガラスに当たったなどで、レーザーが戻ってこなかった点です

```python
scan = rc.lidar.get_samples()
print(len(scan))           # 720（点の数）
print(scan[0])             # 真正面までの距離（cm）
```

壁までの距離を正しく測る方法は、第6章の壁沿い走行で詳しく扱います。

### IMU：加速度と角速度

IMU は、車がどう動いているかを測るセンサです。どちらも**3つの軸**についての値を、3つの数の並びで返します。

- **加速度**：速さがどれだけ変わっているか。アクセルを踏むと進む向きの値が、ブレーキで反対向きの値が出ます
- **角速度**：どれだけの速さで回っているか。ハンドルを切って曲がると、上下の軸まわりの値が変わります

車が止まっていても、加速度の上下方向の軸には**約9.8**という大きな値が出ます。これは重力の影響です。3つの軸がそれぞれどの向きかは、シミュレータと実機で違います。IMU は第5章で詳しく扱うので、ここでは「止まっていても重力の分の値が出る」ことだけ覚えておきましょう。

### センサ点検プログラム

3つのセンサの値を、1秒に1回まとめて表示するプログラムです。表示は `update_slow()` に書きます（1-3 で学んだとおり、`update()` で表示すると文字であふれるからです）。

```python:sensor_check.py
import racecar_core

rc = racecar_core.create_racecar()


def start():
    rc.drive.stop()


def update():
    pass


def update_slow():
    image = rc.camera.get_color_image()
    scan = rc.lidar.get_samples()
    accel = rc.physics.get_linear_acceleration()
    ang_vel = rc.physics.get_angular_velocity()
    n = len(scan)                  # 届いた配列の長さ＝点の数

    print("---- センサ点検 ----")
    print(f"カメラ画像の形: {image.shape}")
    print(f"LIDAR の点の数: {n}")
    print(f"真正面まで: {scan[0]:.1f} cm / 真後ろまで: {scan[n // 2]:.1f} cm")
    print(f"加速度 [m/s²]: {accel.round(2)}")
    print(f"角速度 [rad/s]: {ang_vel.round(2)}")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

User Program モードで動かすと、1秒に1回、次のような形の表示が出ます。

```text
---- センサ点検 ----
カメラ画像の形: (480, 640, 3)
LIDAR の点の数: 720
真正面まで: （前の壁までの距離） cm / 真後ろまで: （後ろの壁までの距離） cm
加速度 [m/s²]: （3つの数）
角速度 [rad/s]: （3つの数）
```

試してみましょう。

- Backspace で手動運転に戻し、車を壁に近づけてから、また Enter で User Program モードに入ります。真正面までの距離が小さくなるはずです
- 手動運転で走っている最中は表示が止まるので、User Program モードのまま、自分でハンドルを切るプログラムを書くのは第3章で行います

:::message
真後ろの番号を `360` と数字で書かずに、`n // 2`（点の数の半分）と書いています。こう書いておけば、もし点の数が変わっても、いつでも真後ろを指します。`//` は「割り算の答えを整数に切り捨てる」記号です。

ライブラリには点の数を返す `rc.lidar.get_num_samples()` という命令もありますが、これはライブラリの中に書かれた決まった数を返すもので、実際に届いた配列を数えるわけではありません。実際に届いた点の数は、`len(scan)` で確かめるのが確実です。
:::

### シミュレータと実機で違うところ

| 項目 | シミュレータ | 実機 |
|---|---|---|
| LIDAR のデータの形 | 720個の小数の配列（真正面から時計回り） | 同じ |
| IMU の軸の向き | シミュレータ独自の割り当て | 実機のセンサの割り当て（第5章） |
| 地磁気 `get_magnetic_field()` | 使えない（`None` が返る） | 使える |
| 車輪の回転の速さ `get_encoder_speed()` | 使えない（0.0 が返る） | 使える |
| バッテリーの電圧・電流 | 使えない（0.0 が返る） | 使える（第9章） |
| 物体検出 `rc.vision` | ない | 使える（第9章） |

この本の第1章〜第8章は、シミュレータで使える命令だけで進めます。

## ⑤ つまずきポイント

### 配列を丸ごと print して、画面が数字で埋まった

`print(scan)` や `print(image)` とすると、720個や 480 × 640 × 3 = 921,600 個の数を表示しようとして、ターミナルが埋まってしまいます。配列は `.shape` や `len()` で大きさを確かめ、中身は `scan[0]` のように必要な1つだけを表示しましょう。

### 番号と角度を取り違えた

RACECAR の LIDAR は0.5°ごとなので、**番号と角度は同じではありません**。右（90°）は番号90ではなく、番号180です。角度から番号を求めるときは、次の式を使います。

$$
\text{番号} = \frac{\text{角度}}{360} \times \text{点の数}
$$

### 距離が 0.0 になった

0.0 は「距離が0」ではなく「測れなかった」という意味です。0.0 をそのまま「すぐ目の前に壁がある」と受け取ると、車が急に止まったり曲がったりします。0.0 を取り除いて扱う方法は、第6章で学びます。

### cm と m を混ぜた

LIDAR と深度画像は **cm**、IMU の加速度は **m/s²** です。距離と速さを組み合わせて計算するときは、単位をそろえてから計算しましょう。

## ⑥ 確認問題

**問1**　シミュレータの LIDAR で、左（270°）と、右ななめ前（45°）の距離は、それぞれ `scan` の何番に入っていますか。

:::details 答え
左は $\frac{270}{360} \times 720 = 540$ 番、右ななめ前は $\frac{45}{360} \times 720 = 90$ 番です。
:::

**問2**　右（90°）の距離を、`scan[180]` と番号を直接書かずに、配列の長さを使って読むには、どう書けばよいですか。

:::details 答え
90° は1周の4分の1なので、`scan[len(scan) // 4]` と書きます。点の数が720個なら `720 // 4 = 180` 番になり、`scan[180]` と同じ点を指します。数字を直接書くより、何を読んでいるのかがわかりやすく、点の数が変わっても正しく右を指します。
:::

**問3**　カメラ画像のある画素が `[0, 0, 255]` でした。この画素は何色ですか。

:::details 答え
赤です。RACECAR のカメラ画像は **青・緑・赤** の順に並んでいるので、3番目（赤）だけが最大の 255 になっています。
:::
