ゲインを変えて走らせたとき、「さっきよりよくなった」と、どうやって決めればよいでしょうか。グラフをながめるだけでは、見る人によって判断が変わります。この回では、目標に近づいていく走りを、**立ち上がり時間・行き過ぎ量・整定時間・残ったずれ**などの数で表します。数で比べると、ゲインのよしあしを、はっきり決められるようになります。

## ① この回でできるようになること

1. ステップ応答（目標が急に変わったときの反応）が何かを説明できる
2. 記録から、立ち上がり時間・行き過ぎ量・整定時間・残ったずれを計算できる
3. いくつかのゲインを、数を並べて比べられる
4. 1つのテストだけでなく、いくつかの場面で確かめる大切さを説明できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Step response | ステップ応答 | 目標から大きく離れた所から、目標に近づいていく反応 |
| Rise time | 立ち上がり時間 | ずれが、はじめの 90% から 10% になるまでの時間 |
| Overshoot | 行き過ぎ量 | 目標をこえて、反対側にいちばん行った量 |
| Settling time | 整定時間 | そのあとずっと、目標のまわりの決めた幅に入っているようになるまでの時間 |

## ③ 本文

### ステップ応答を見る

制御のよしあしを比べるときは、**いつも同じ条件**で走らせます。ここでは、「右の壁から 100 cm の所から走り出して、目標の 50 cm に近づいていく」走りを使います。はじめに 50 cm のずれがあり、それがどう減っていくかを見ます。このように、目標から一気に離れた所から始まる反応を、**ステップ応答**といいます。

| 数 | 求め方 | 何がわかるか |
|---|---|---|
| **立ち上がり時間** | ずれが、はじめの 90% から 10% になるまでの時間 | 目標に近づく速さ。短いほど、すばやい |
| **行き過ぎ量** | 目標をこえて、反対側にいちばん行った量 | 行き過ぎの大きさ。小さいほど、安全 |
| **整定時間** | そのあとずっと、目標 ± 2.5 cm に入っているようになるまでの時間 | 落ち着くまでの時間。短いほどよい |
| **残ったずれ** | 最後の 2 秒のずれの平均 | 落ち着いたあとのずれ。0 に近いほどよい |

もう1つ、**ハンドルの動き**（1秒あたりに、angle がどれだけ動いたかの合計）も見ておきます。ハンドルをせわしなく動かすと、実物の車ではタイヤがすべりやすくなり、サーボモーターもいたみます。同じくらいの走りなら、ハンドルの動きが少ないほうがよい制御です。

### 記録をとる

6-12 の `wall_follow_pid.py` に、6-8 と同じように記録をとる行を足します。`wall_follow_pid_log.py` という名前で保存しましょう。

### やってみよう：記録から4つの数を計算する

記録（`wall_log.csv`）を読んで、4つの数とハンドルの動きを計算するプログラムです。6-8 の `plot_log.py` と同じく、ふつうの Python で動かします。

```python:evaluate_log.py
"""
evaluate_log.py
wall_log.csv を読んで、反応のよさを数で表す（6-13）。
はじめの距離から TARGET へ近づいていく走り（ステップ応答）を調べる。
"""

import csv

TARGET = 50.0     # 目標の距離（cm）
BAND = 2.5        # この幅（± cm）の中に入り続けたら「落ち着いた」とみなす

times, dists, angles = [], [], []
with open("wall_log.csv") as f:
    for row in csv.DictReader(f):
        times.append(float(row["time"]))
        dists.append(float(row["distance"]))
        angles.append(float(row["angle"]))

step = dists[0] - TARGET                        # はじめのずれ
ratio = [(d - TARGET) / step for d in dists]    # はじめのずれを 1 としたときの、今のずれ

# 1. 立ち上がり時間：ずれが、はじめの 90% から 10% になるまでの時間
t90 = next(t for t, r in zip(times, ratio) if r <= 0.9)
t10 = next(t for t, r in zip(times, ratio) if r <= 0.1)
rise = t10 - t90

# 2. 行き過ぎ量：目標をこえて、反対側にいちばん行った量
overshoot = max(0.0, -min(ratio)) * abs(step)

# 3. 整定時間：最後に BAND の外にいた時刻（そのあとは、ずっと BAND の中）
outside = [t for t, d in zip(times, dists) if abs(d - TARGET) > BAND]
settle = outside[-1] if outside else 0.0

# 4. 残ったずれ：最後の 2 秒のずれの平均
last = [d - TARGET for t, d in zip(times, dists) if t > times[-1] - 2.0]
steady = sum(last) / len(last)

# 5. ハンドルの動き：1秒あたりに、angle がどれだけ動いたかの合計
moves = sum(abs(a1 - a0) for a0, a1 in zip(angles[:-1], angles[1:]))
activity = moves / (times[-1] - times[0])

print(f"はじめのずれ   {step:+6.1f} cm")
print(f"立ち上がり時間 {rise:6.2f} 秒")
print(f"行き過ぎ量     {overshoot:6.1f} cm（はじめのずれの {overshoot / abs(step) * 100:.0f}%）")
print(f"整定時間       {settle:6.2f} 秒（± {BAND} cm）")
print(f"残ったずれ     {steady:+6.2f} cm")
print(f"ハンドルの動き {activity:6.2f}（1秒あたり）")
```

- `ratio`：はじめのずれを 1 としたときの、今のずれです。1 から始まって、0 に近づいていきます。目標をこえると－になります
- `next(t for t, r in zip(times, ratio) if r <= 0.9)`：条件にあう**最初の**時刻を取り出します
- 整定時間は、「最後に幅の外にいた時刻」として求めています。その時刻より後は、ずっと幅の中にいるからです

説明用の簡単なモデルで、壁から 100 cm の所から 12 秒走らせた記録を調べると、次のように表示されました。

```text
はじめのずれ    +50.5 cm
立ち上がり時間   2.18 秒
行き過ぎ量        3.6 cm（はじめのずれの 7%）
整定時間         7.87 秒（± 2.5 cm）
残ったずれ      -0.48 cm
ハンドルの動き   0.77（1秒あたり）
```

数を並べると、それぞれのゲインの性格が見えてきます。

- **イ（壁の向きのゲインを小さく）**：立ち上がりは速いが、ブレーキが弱く、15 cm も行き過ぎる
- **ウ（壁の向きのゲインを大きく）**：ブレーキが強すぎて、近づくのが遅い。ハンドルの動きも大きい（壁の向きのばらつきを、大きく増やしてしまう）
- **エ（KP を大きく）**：立ち上がりも整定も速い。行き過ぎも小さい
- **オ（I なし）**：まっすぐな壁では、いちばん行き過ぎが小さく、整定も速い。でも、丸い部屋では 15 cm のずれが残る
- **カ（KI を大きく）**：I がためすぎて、行き過ぎが大きく、なかなか落ち着かない

大事なのは、オです。まっすぐな壁のテストだけなら、オがいちばんよく見えます。でも、丸い部屋では、ずれが残ってしまいます。**1つのテストだけで決めず、まっすぐな壁・曲がった壁・はじめのずれが大きいとき、のように、いくつかの場面で確かめる**ことが大切です。この表の中では、どの場面でも大きな弱点のないエがよさそうです。

### どの数を大事にするか

どの数を大事にするかは、目的で変わります。

- **タイムアタック**（6-20）：少しくらい行き過ぎても、立ち上がりが速いほうがよい。ただし、壁にぶつからない範囲で
- **せまい通路**（6-18）：行き過ぎると壁にぶつかるので、行き過ぎ量を小さくしたい
- **実物の車**：ハンドルの動きが大きいと、タイヤがすべって、モデルやシミュレータのようには走らない

目的を決めてから、「この数は、これより小さく」という目安をつくっておくと、ゲインを決める作業（6-14）が進めやすくなります。

## ④ 数式・コード

### 立ち上がり時間と、行き過ぎ量の関係

表のイ・ア・ウを比べると、壁の向きのゲイン（ブレーキ）を大きくするほど、立ち上がりは遅くなり、行き過ぎは小さくなる傾向があります（ウは I のため少し行き過ぎています）。速さと行き過ぎの少なさは、たいてい**どちらかをとれば、どちらかが悪くなる**関係にあります。これを**トレードオフ**といいます。

### 行き過ぎ量を % で表す

行き過ぎ量は、はじめのずれに対する割合（%）でも表します。

$$
\text{行き過ぎ量（\%）} = \frac{\text{行き過ぎ量}}{|\text{はじめのずれ}|} \times 100
$$

% にしておくと、はじめのずれが 50 cm のときと 30 cm のときの走りも比べられます。

## ⑤ つまずきポイント

### `StopIteration` というエラーが出る

`next(...)` で、条件にあう時刻が1つもないと、このエラーになります。たとえば、記録が短すぎて、ずれがはじめの 10% まで減らないうちに終わった場合です。もっと長く走らせてから記録を調べましょう。

### 毎回、数がちがう

シミュレータの LIDAR にはばらつきがあるので、同じゲインでも、走らせるたびに少しずつ数が変わります。大事な比べっこでは、同じゲインで何回か走らせて、平均をとりましょう。

### はじめの位置がそろっていない

はじめのずれがちがうと、立ち上がり時間や行き過ぎ量も変わります。比べる走りは、できるだけ同じ所から走り出すようにします。シミュレータでは、Lab I の探索モードで、同じチェックポイントから始めると、そろえやすくなります。

## ⑥ 確認問題

**問1**　はじめのずれが +40 cm で、いちばん行き過ぎたとき、距離は目標より 6 cm 近い所でした。行き過ぎ量は何 % ですか。

:::details 答え
$6 \div 40 \times 100 = 15$ % です。
:::

**問2**　ずれが、はじめの 90% になったのが 1.2 秒、10% になったのが 3.0 秒でした。立ち上がり時間は何秒ですか。

:::details 答え
$3.0 - 1.2 = 1.8$ 秒です。
:::

**問3**　表のオ（I なし）は、まっすぐな壁ではいちばんよい数でした。それでも、オを選ばないほうがよいのはなぜですか。

:::details 答え
丸い部屋（曲がった壁）では、15 cm のずれが残るからです。1つのテストだけでは、弱点が見えないことがあります。
:::
