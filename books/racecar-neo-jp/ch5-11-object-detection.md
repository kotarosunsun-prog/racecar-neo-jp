5-6〜5-10 で、データから学ぶしくみを学びました。この回からは、それを使って、カメラの画像の中から「コーン」や「人」を見つける**物体検出**に進みます。まず、物体検出のモデルが何を答えるのか、そして、その答えをどう読んで、どう評価するのかを学びます。5-12〜5-14 では、実際に自分のデータで物体検出のモデルを作ります。

## ① この回でできるようになること

1. 物体検出の答え（名前・自信・枠）の形を説明できる
2. 枠の2つの表し方（左上と右下／中心と大きさ）を行き来できる
3. 2つの枠の重なり具合（IoU）を計算し、重なった枠をまとめるしくみ（NMS）を説明できる
4. 画像を見るニューラルネットワークの入り口にある「たたみこみ」を、例で説明できる
5. 実機で `rc.vision.get_detections()` の答えを読み、プログラムで使える

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |

## ③ 本文

### 分類と物体検出

5-6 の「緑か青か」のように、画像1枚に1つの答えを出すのが**分類**です。物体検出は、画像の中にある物の**1つ1つ**について、次の3つを答えます。

- **名前**（クラス）：何が写っているか
- **自信**（スコア）：その答えがどれくらい確かか（0〜1）
- **枠**（バウンディングボックス）：どこに写っているか

![説明用に作った画像に、物体検出の答えを描いたもの。左の大きいコーンには緑の枠と「cone 0.91」、右の小さいコーンには「cone 0.77」。まん中の茶色い箱には点線の枠と「cone 0.22」がついているが、自信がしきい値 0.4 より低いので捨てる。左のコーンの枠は、左上が (100, 200)、右下が (180, 320)、中心 (x, y) が (140, 260)、幅 80、高さ 120](/images/racecar-neo-jp/5-11/fig1-detections.png)
*図1　物体検出の答え：名前・自信・枠（説明用に作った画像と値）*

物体検出のモデルは、たくさんの答えの候補を出します。中には、図1のまん中の箱のように、自信の低いまちがった答えもまじります。そこで、自信が**しきい値**より低い答えは捨てます。実機の Edge TPU のプログラムでは、このしきい値が 0.4 に設定されています。

### 枠の2つの表し方

枠の表し方には、よく使われるものが2つあります。

| 表し方 | 図1の左のコーン | 使われるところ |
|---|---|---|
| 左上と右下 $(x_{\min}, y_{\min}, x_{\max}, y_{\max})$ | (100, 200, 180, 320) | 5-13 の正解付け（Pascal VOC 形式） |
| 中心と大きさ $(x_c, y_c, w, h)$ | (140, 260, 80, 120) | 実機の `rc.vision.get_detections()` |

2つは、次の式で行き来できます。

$$
x_c = \frac{x_{\min} + x_{\max}}{2}, \quad
y_c = \frac{y_{\min} + y_{\max}}{2}, \quad
w = x_{\max} - x_{\min}, \quad
h = y_{\max} - y_{\min}
$$

:::message alert
**(x, y) と (行, 列) の順番に注意**
物体検出の枠は、**x（左から右）が先、y（上から下）があと**の順で書きます。5-1〜5-4 で使った `racecar_utils` の (行, 列) とは、順番が逆です。x は「列」、y は「行」にあたります。
:::

### 重なり具合を測る：IoU

2つの枠がどれくらい重なっているかを、**IoU** という数で表します。

![IoU の説明図。予想の枠と正解の枠が一部重なっている。IoU は、重なった部分の面積を、予想の枠と正解の枠の面積を足して重なりを引いたもの（2つを合わせた面積）で割ったもの。ぴったり同じなら 1、まったく重ならなければ 0。評価では「IoU が 0.5 以上なら当たり」のように使う](/images/racecar-neo-jp/5-11/fig2-iou.png)
*図2　IoU：2つの枠の重なり具合*

$$
\text{IoU} = \frac{\text{重なった部分の面積}}{\text{2つの枠を合わせた面積}}
$$

IoU は、次の2つの場面で使います。

- **評価**：モデルが出した枠と、正解の枠の IoU が 0.5 以上なら「当たり」とする、のように使う（④）
- **NMS**：同じ物に出た、重なった枠をまとめる

### 重なった枠をまとめる：NMS

物体検出のモデルは、1つの物に対して、少しずつずれた枠をいくつも出すことがあります。これをまとめるのが **NMS** です。

1. 枠を、自信の高い順に並べる
2. いちばん自信の高い枠を残す
3. 残した枠と大きく重なる（IoU が 0.5 以上などの）枠は、同じ物を指しているとみなして捨てる
4. 残りの枠で、2 と 3 をくり返す

![左は NMS の前で、左のコーンに自信 0.91、0.84、0.62 の3つの枠が少しずつずれて重なり、右のコーンに 0.77 の枠が1つある。右は NMS の後で、左のコーンには自信がいちばん高い 0.91 の枠だけが残り、右のコーンの 0.77 の枠もそのまま残っている](/images/racecar-neo-jp/5-11/fig3-nms.png)
*図3　NMS の前と後*

```python:iou_nms.py
"""
iou_nms.py
2つの枠の重なり具合（IoU）と、重なった枠を1つにまとめる NMS を計算する。
枠は (左の x, 上の y, 右の x, 下の y) の画素で表す。
"""


def iou(a, b):
    """2つの枠の IoU（重なりの面積 ÷ 2つを合わせた面積）"""
    left = max(a[0], b[0])
    top = max(a[1], b[1])
    right = min(a[2], b[2])
    bottom = min(a[3], b[3])
    overlap = max(0, right - left) * max(0, bottom - top)     # 重なった部分の面積
    area_a = (a[2] - a[0]) * (a[3] - a[1])
    area_b = (b[2] - b[0]) * (b[3] - b[1])
    return overlap / (area_a + area_b - overlap)


def nms(boxes, scores, iou_threshold=0.5):
    """自信の高い順に選び、選んだ枠と大きく重なる枠は捨てる"""
    order = sorted(range(len(boxes)), key=lambda i: scores[i], reverse=True)
    keep = []
    for i in order:
        if all(iou(boxes[i], boxes[k]) < iou_threshold for k in keep):
            keep.append(i)
    return keep


# 同じコーンに3つの枠が重なって出て、別のコーンに1つ出た、という例
boxes = [(100, 200, 180, 320), (108, 196, 190, 316), (96, 210, 176, 330), (400, 230, 450, 300)]
scores = [0.91, 0.84, 0.62, 0.77]

print(f"枠0 と 枠1 の IoU：{iou(boxes[0], boxes[1]):.2f}")
print(f"枠0 と 枠3 の IoU：{iou(boxes[0], boxes[3]):.2f}")
print("NMS で残った枠：", nms(boxes, scores))
```

```text
枠0 と 枠1 の IoU：0.75
枠0 と 枠3 の IoU：0.00
NMS で残った枠： [0, 3]
```

5-14 で作るモデルは、書き出すときに NMS の段がモデルの最後に組みこまれるので、実機では自分で NMS を書く必要はありません。しくみとして知っておきましょう。

### モデルの中では、何をしているのか：たたみこみ

画像を見るニューラルネットワークの入り口では、**たたみこみ**という計算が使われます。3×3 のような小さな数の表（**フィルタ**）を、画像の上で1画素ずつずらしながら重ね、重なったところの「画素の値 × フィルタの値」を足し合わせます。

![左は白黒にした入力の画像で、コーン2つと箱が写っている。まん中は 3×3 のフィルタで、左の列が −1、−2、−1、まん中の列が 0、右の列が 1、2、1。右はフィルタをかけた結果（特徴マップ）で、コーンのふちや箱の左右のふちのような、縦の境目だけが光っている](/images/racecar-neo-jp/5-11/fig4-convolution.png)
*図4　たたみこみの例：左右の明るさの差に反応するフィルタ（説明用に作った画像）*

図4のフィルタは、「右側が明るく、左側が暗い（またはその逆）」ところで大きな値になります。そのため、結果の画像（**特徴マップ**）では、物の**縦のふち**だけが光ります。

物体検出のモデルは、このようなフィルタを何百個も持ち、何十層も重ねています。そして、フィルタの数も、5-10 の誤差逆伝播で**学習して**決めます。入口に近い層は「ふち」「色の境目」のような単純な形に、奥の層は「三角のとんがり」「しま模様」「コーンの形」のような複雑な形に反応するようになります。モデルの最後の段は、特徴マップのあちこちの場所ごとに、「ここに物があるなら、名前は何で、枠はどこか」を答えます。

5-14 で使う **EfficientDet-Lite0** は、スマートフォンや Edge TPU のような小さな機械で速く動くように作られた物体検出のモデルで、画像を 320×320 画素に縮めてから見ます。

### 実機で答えを受けとる：rc.vision.get_detections()

実機では、Edge TPU で動く物体検出の結果を、次の関数で受けとれます（シミュレータにはありません）。

```python
detections = rc.vision.get_detections()
```

見つけた物ごとに、次の3つが入ったリストが返ります。自信がしきい値（0.4）より低いものは、はじめから入っていません。

| 書き方 | 中身 |
|---|---|
| `det.class_id` | 名前（ラベルのファイルに書いた名前の文字列） |
| `det.score` | 自信（0〜1） |
| `det.bbox` | 枠の (中心の x, 中心の y, 幅, 高さ)。カメラの画像（横 640 × 縦 480）の画素 |

次のプログラムは、いちばん自信の高い「cone」のほうへ、ハンドルだけを切ります。コーンが画面の左にあれば左に、右にあれば右に切ります。

```python:detect_follow.py
"""
detect_follow.py（実機用）
Edge TPU が見つけた物のうち、いちばん自信の高い「cone」のほうへ、ハンドルだけを切る。
速さは 0 のままなので、車は進まない。RB を押している間だけ、プログラムの命令が車に届く。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core

rc = racecar_core.create_racecar()

TARGET = "cone"     # 追いかける物の名前（ラベルのファイルに書いた名前と同じにする）
MIN_SCORE = 0.5     # これより自信が低い答えは使わない


def find_target():
    """いちばん自信の高い TARGET の検出結果を返す。なければ None"""
    best = None
    for det in rc.vision.get_detections():
        if det.class_id == TARGET and det.score >= MIN_SCORE:
            if best is None or det.score > best.score:
                best = det
    return best


def start():
    rc.drive.stop()
    rc.set_update_slow_time(0.5)
    print(f">> {TARGET} のほうへハンドルを切ります（RB を押している間）")


def update():
    target = find_target()
    angle = 0.0
    if target is not None:
        center_x = target.bbox[0]                 # 枠の中心の x（左から何画素め）
        half = rc.camera.get_width() / 2          # 画面の真ん中の x
        angle = (center_x - half) / half          # 左はしで -1、真ん中で 0、右はしで +1
        angle = max(-1.0, min(1.0, angle))        # 念のため -1〜1 に収める
    rc.drive.set_speed_angle(0.0, angle)


def update_slow():
    target = find_target()
    if target is None:
        print(f"{TARGET} は見つかっていません")
    else:
        print(target)


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

図1と同じ答えを渡すと、左のコーン（中心の x が 140）を選び、`angle` は $(140 - 320) / 320 \approx -0.56$（左）になりました。表示は次のようになります。

```text
Detection(class_id='cone', score=0.91, bbox=(140, 260, 80, 120))
```

ずれに比例してハンドルを切るこの考え方は、第6章の**比例制御**そのものです。実機では、2-4 で学んだように、RB を押している間だけプログラムの命令が車に届きます。

## ④ 数式・コード

### 物体検出の評価：適合率と再現率

モデルのできばえは、テスト用データで、次の2つの数を使って表します。IoU が 0.5 以上なら「当たり」とします。

$$
\text{適合率} = \frac{\text{当たりの数}}{\text{モデルが出した枠の数}}, \qquad
\text{再現率} = \frac{\text{当たりの数}}{\text{正解の枠の数}}
$$

- **適合率**（Precision）：モデルが「ある」と言ったもののうち、本当にあった割合。まちがった答え（空振り）が少ないほど高い
- **再現率**（Recall）：本当にあったもののうち、モデルが見つけられた割合。見のがしが少ないほど高い

自信のしきい値を上げると、空振りが減って適合率は上がりますが、見のがしが増えて再現率は下がります。しきい値を少しずつ変えながら、再現率のいろいろな値での適合率を平均した数を **AP**（Average Precision）といいます。5-14 で学習したモデルの評価に出てくる AP50 は「IoU が 0.5 以上を当たりとしたときの AP」、AP は「IoU の基準を 0.5〜0.95 まで変えて平均した AP」です。

### 自分でたたみこみを計算する

OpenCV の `cv.filter2D()` を使うと、図4と同じ計算ができます。

```python
import cv2 as cv
import numpy as np

gray = cv.cvtColor(image, cv.COLOR_BGR2GRAY).astype(np.float32)     # 白黒にする
kernel = np.array([[-1, 0, 1],
                   [-2, 0, 2],
                   [-1, 0, 1]], np.float32)                          # 縦の境目に反応するフィルタ
feature_map = np.abs(cv.filter2D(gray, -1, kernel))                  # たたみこみ
```

フィルタを90°回した表（上の行が −1、−2、−1、下の行が 1、2、1）に変えると、今度は**横の**境目に反応します。

## ⑤ つまずきポイント

### x と y、行と列を取り違える

`det.bbox[0]` は枠の中心の **x**（左から何画素め）、`det.bbox[1]` は **y**（上から何画素め）です。`racecar_utils` の関数に渡すときは、(行, 列) ＝ (y, x) の順に並べ替えます。

### シミュレータで `rc.vision` を使ったらエラーになった

シミュレータには Edge TPU がないので、`rc.vision` はありません。物体検出を使うプログラムは、実機で動かします。

### 自信のしきい値を上げたら、何も見つからなくなった

しきい値を上げすぎると、見のがしが増えます。実機のドライバの説明にも、しきい値を 0.5 にしたら、ふつうの部屋の中で何も見つからなくなったと書かれています。自分のプログラムの `MIN_SCORE` も、実際に試しながら決めましょう。

### 1つの物に、枠が2つ出る

NMS の IoU のしきい値より重なりが小さい枠は、別の物とみなされて残ります。プログラムの中で、いちばん自信の高いものだけを使う（`detect_follow.py` の `find_target()` のように）と、影響を受けにくくなります。

## ⑥ 確認問題

**問1**　枠が (中心の x, 中心の y, 幅, 高さ) ＝ (300, 200, 60, 100) で表されています。左上と右下の角の座標を求めましょう。

:::details 答え
左上は $(300 - 30,\ 200 - 50) = (270, 150)$、右下は $(300 + 30,\ 200 + 50) = (330, 250)$ です。
:::

**問2**　枠 A が (0, 0, 10, 10)、枠 B が (5, 0, 15, 10) です（左上と右下の表し方）。IoU を求めましょう。

:::details 答え
重なった部分は (5, 0, 10, 10) で、面積は $5 \times 10 = 50$ です。A と B の面積はどちらも 100 なので、2つを合わせた面積は $100 + 100 - 50 = 150$ です。IoU は $50 \div 150 \approx 0.33$ です。
:::

**問3**　テスト用の写真にコーンが全部で 20 個写っていて、モデルは枠を 16 個出しました。そのうち 12 個が当たりでした。適合率と再現率を求めましょう。

:::details 答え
適合率は $12 \div 16 = 0.75$、再現率は $12 \div 20 = 0.6$ です。空振りが 4 個、見のがしが 8 個あったことになります。
:::

**問4**　`detect_follow.py` で、コーンの枠の中心の x が 480 のとき、`angle` はいくつですか。

:::details 答え
$(480 - 320) \div 320 = 0.5$ です。右に半分ハンドルを切ります。
:::
