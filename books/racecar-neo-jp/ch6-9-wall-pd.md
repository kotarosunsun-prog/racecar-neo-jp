6-8 で、P 制御だけでは揺れが止まらない理由がわかりました。目標に勢いよく近づいていても、ずれが 0 になるまでハンドルをもどさないので、行き過ぎるのです。この回では、**ずれが変わる速さ**を計算して、早めにハンドルをもどす **D（微分）** を加えます。

## ① この回でできるようになること

1. ずれが変わる速さを、記録したずれから計算できる
2. P に D を足すと、行き過ぎがおさえられる理由を説明できる
3. 速さを1コマで求めると、うまくいかない理由を説明できる
4. 何コマか前のずれと比べて、落ち着いた速さを求められる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Derivative (D) | 微分（D） | 値が変わる速さ。ここでは、ずれが1秒あたり何 cm 変わるか |
| Rate of change | 変化の速さ | ある時間の間に、どれだけ変わったかを、時間でわったもの |
| Damping | 減衰（ブレーキ） | 揺れをだんだん小さくするはたらき |
| PD control | PD 制御 | P（ずれ）と D（ずれの変わる速さ）を足して命令を決める方法 |

## ③ 本文

### ずれが変わる速さ

ずれが、あるコマで $e_1$、その少しあとのコマで $e_2$ だったとします。その間の時間を $\Delta t$ とすると、ずれが変わる速さは、

$$
\text{rate} = \frac{e_2 - e_1}{\Delta t}
$$

です。単位は「cm/秒」です。rate が－なら、ずれが**減っている**（＋のずれが縮んでいる、つまり壁に近づいている）ことを表します。

### D がブレーキになるわけ

D 制御では、この速さに KD をかけたものを、P に足します。

$$
\text{angle} = K_P \times \text{error} + K_D \times \text{rate}
$$

たとえば、壁から 60 cm（ずれ +10 cm）の所を、1秒に 30 cm の速さで壁に近づいているとします（rate = −30 cm/秒）。`KP = 0.02`、`KD = 0.03` なら、

- P の部分：$0.02 \times 10 = +0.2$（壁のほうへ）
- D の部分：$0.03 \times (-30) = -0.9$（壁から離れるほうへ）
- 合計：$+0.2 - 0.9 = -0.7$

P だけなら、まだ壁のほうへハンドルを切り続けます。D を足すと、まだ目標に着く前なのに、ハンドルを反対に切り始めます。**勢いよく近づいているほど、早めにブレーキをかける**、というはたらきです。6-8 のばねとおもりでいえば、動きにブレーキをかけるダンパ（減衰器）の役目です。

### はじめの考え：1コマで速さを求める

いちばん簡単なのは、前のコマのずれと、今のコマのずれを比べる方法です。

```python
rate = (error - prev_error) / rc.get_delta_time()   # 1コマで速さを求める
prev_error = error
angle = rc_utils.clamp(KP * error + KD * rate, -1.0, 1.0)
```

説明用の簡単なモデルで、LIDAR にばらつきも遅れもないようにして試すと、この方法でうまく走れました。ところが、6-6 と同じように、距離の 2% のばらつきと、1秒に6回転する LIDAR を入れると、**2.6秒で壁にぶつかりました**。

*図1　速さを1コマで求めたときと、10コマで求めたとき（説明用の簡単なモデル）*

図1の上の灰色の線が、1コマで求めた速さです。**ほとんどのコマで 0** で、ときどき、とても大きな値がとげのように出ます。理由は2つあります。

- **LIDAR の値は、1秒に 10 回くらいしか変わらない**（6-6・6-8）。値が変わらないコマでは、速さは 0 になる。値が変わったコマでは、その間の変化がまとめて1コマの変化になるので、とても大きな速さになる
- **ばらつきが、大きく増やされる**。1 cm のばらつきでも、1コマ（1/60 秒）でわると、60 cm/秒の速さに見えてしまう

その結果、ハンドルは、P だけの角度と、いっぱいの反対（−1）の間で、何度も切りかわりました（図1の下の灰色の線）。これでは、ブレーキとしてはたらきません。

### 何コマか前と比べて、速さを求める

そこで、**1コマ前ではなく、何コマか前のずれと比べて**、速さを求めます。LIDAR がちょうど1回転するくらいの時間（1/6 秒 ＝ 10コマ）の間の変化を使えば、とげは消え、ばらつきも 10 分の 1 くらいになります。

最近のずれを、リストにためておきます。第4章の命令の列と同じように、新しいものを後ろに足し（`append`）、古いものを前から捨てます（`pop(0)`）。

```python
errors.append(error)
if len(errors) > RATE_FRAMES + 1:
    errors.pop(0)            # 古いずれを捨てる（RATE_FRAMES + 1 個を残す）

rate = 0.0
if len(errors) >= 2:
    frames = len(errors) - 1
    rate = (errors[-1] - errors[0]) / (frames * rc.get_delta_time())
```

`errors[-1]` がいちばん新しいずれ、`errors[0]` が `RATE_FRAMES` コマ前のずれです。図1のオレンジの線が、この方法で求めた速さです。階段のような形ですが、本当の速さ（黒い点線）にそっています。

### やってみよう：P ＋ D で壁にそって走る

```python:wall_follow_pd.py
"""
wall_follow_pd.py
右の壁から TARGET cm の距離を保って走る（P ＋ D）。
D には、ずれが縮む速さを、LIDAR が1回転するくらいの時間（RATE_FRAMES コマ）で求めて使う。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

TARGET = 50.0     # 右の壁から保ちたい距離（cm）
SPEED = 0.5       # 走る速さ（一定）
KP = 0.02         # P のゲイン
KD = 0.03         # D のゲイン
RATE_FRAMES = 10  # 何コマ前のずれと比べて、速さを求めるか
MAX_WALL = 300.0  # これより遠いときは「壁なし」とみなす

distance = None   # 右の壁までの距離（update_slow で表示する）
angle = 0.0
rate = 0.0        # ずれの変わる速さ（cm/秒）
errors = []       # 最近のずれ（古い順）


def right_wall_distance(scan):
    """右の壁までの距離（cm）。壁が見つからなければ None（6-6）"""
    closest_angle, closest = rc_utils.get_lidar_closest_point(scan, (45, 135))
    if closest > MAX_WALL:
        return None
    center = round(closest_angle * len(scan) / 360)
    near = []
    for d in scan[center - 10 : center + 11]:
        if 0 < d < closest + 5:
            near.append(d)
    return sum(near) / len(near)


def start():
    rc.drive.stop()
    errors.clear()
    print(f">> 右の壁から {TARGET:.0f} cm を保って走ります（P ＋ D、KP = {KP}、KD = {KD}）")


def update():
    global distance, angle, rate

    scan = rc.lidar.get_samples()
    distance = right_wall_distance(scan)

    if distance is None:
        angle = 0.0                  # 壁が見えないときは、まっすぐ
        errors.clear()               # 記録も消して、また見えたらやり直す
    else:
        error = distance - TARGET
        errors.append(error)
        if len(errors) > RATE_FRAMES + 1:
            errors.pop(0)            # 古いずれを捨てる（RATE_FRAMES + 1 個を残す）

        rate = 0.0
        if len(errors) >= 2:
            frames = len(errors) - 1
            rate = (errors[-1] - errors[0]) / (frames * rc.get_delta_time())

        angle = rc_utils.clamp(KP * error + KD * rate, -1.0, 1.0)

    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    if distance is None:
        print("壁が見えない")
    else:
        print(f"右の壁まで {distance:5.1f} cm　ずれ {distance - TARGET:+5.1f} cm　速さ {rate:+6.1f} cm/秒　angle {angle:+.2f}")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

右の壁まで  89.7 cm　ずれ +39.7 cm　速さ  -23.4 cm/秒　angle +0.09
右の壁まで  64.3 cm　ずれ +14.3 cm　速さ  -17.5 cm/秒　angle -0.24

図2は、同じ所から、P だけ、P ＋ D（KD 0.01）、P ＋ D（KD 0.03）で走らせた道すじです。

- **P だけ**：大きく行き過ぎて、壁にぶつかった（6-7 でも、はじめのずれが大きいと危ないことを見た）
- **KD = 0.01**：ブレーキが弱い。23 cm まで行き過ぎてから、揺れながら目標にもどる
- **KD = 0.03**：ブレーキがちょうどよい。行き過ぎずに、目標に落ち着く

### KD の決め方

KD は、0 から少しずつ大きくしていきます。

1. まず KD = 0 で、P の揺れ方を見る（6-7・6-8）
2. KD を少し大きくすると、行き過ぎが小さくなり、揺れが早くおさまるようになる
3. 行き過ぎがなくなったら、そのあたりで止める

KD を大きくしすぎると、ブレーキが強すぎて、目標に近づくのが遅くなります。また、速さのばらつきが大きく効いて、ハンドルが細かくふるえるようになります。

`RATE_FRAMES` も、決めなければならない数です。モデルで、`KD = 0.03` のまま `RATE_FRAMES` を変えて走らせると、次のようになりました（ふるえの大きさは、angle のコマごとの変化の標準偏差）。

| RATE_FRAMES | 1 | 5 | 10 | 20 |
|---|---|---|---|---|
| 走りの結果 | 2.6秒で壁にぶつかった | 目標に落ち着く | 目標に落ち着く | 目標に落ち着く |
| ハンドルのふるえ | 0.57 | 0.24 | 0.07 | 0.04 |

`RATE_FRAMES` を大きくすると、ふるえは小さくなります。でも、そのぶん、速さは「少し前の速さ」になり、遅れが増えます（④）。この本では、LIDAR が1回転する時間に合わせて 10 にしました。

## ④ 数式・コード

### KD の単位

rate の単位は cm/秒、angle には単位がないので、KD の単位は「秒/cm」です。`KD = 0.03` は、「1秒に 1 cm の速さでずれが変わるごとに、angle を 0.03 ずつ変える」という意味です。

### 何コマかで求めた速さは、その間の平均の速さ

$N$ コマ前のずれを $e_{-N}$、今のずれを $e_0$、1コマの時間を $\Delta t$ とすると、

$$
\text{rate} = \frac{e_0 - e_{-N}}{N \, \Delta t}
$$

これは、$N$ コマの間の**平均の速さ**です。$N$ を大きくすると、ばらつきは小さくなりますが、平均をとる期間の真ん中は $\dfrac{N}{2}$ コマ前なので、およそ $\dfrac{N \, \Delta t}{2}$ 秒だけ遅れた速さになります。$N = 10$ なら、約 0.08 秒の遅れです。

### D の名前の由来

「変わる速さ」を、時間をとても短くして求めたものを、数学では**微分**（derivative）といいます。D 制御の D は、この頭文字です。プログラムでは、時間をとても短くはできないので、この回のように、何コマかの差で近い値を求めます。

## ⑤ つまずきポイント

### 走り始めに、ハンドルがおかしな動きをする

最初のコマは、ずれが1つしかないので、速さを計算できません。このプログラムでは、`len(errors) >= 2` になるまで、rate を 0 にしています。前のコマのずれを `prev_error = 0` のように決めておくと、最初のコマで「ずれが急に大きくなった」と計算されて、ハンドルが大きく切られてしまいます。

### 壁が見えなくなったあと、急にハンドルを切る

壁が見えない間に、記録が古いまま残っていると、壁がまた見えたとき、古いずれと新しいずれの差が、大きな速さに見えます。このプログラムでは、壁が見えないときに `errors.clear()` で記録を消しています。

### 壁の段差や入り口で、ハンドルがぴくっと動く

壁が急に近くなる所（段差）では、ずれが1コマで大きく変わるので、速さがとても大きくなり、D の部分が大きくはたらきます。6-10 の方法では、この問題が小さくなります。

## ⑥ 確認問題

**問1**　10コマ前のずれが +20.0 cm、今のずれが +16.0 cm でした。1コマは 1/60 秒です。ずれの変わる速さは何 cm/秒ですか。

:::details 答え
$(16.0 - 20.0) \div (10 \div 60) = -4 \div 0.1667 \approx -24$ cm/秒です。1秒に 24 cm の速さで、ずれが減っています（壁に近づいています）。
:::

**問2**　問1 のとき、`KP = 0.02`、`KD = 0.03` なら、angle はいくつですか。

:::details 答え
$0.02 \times 16 + 0.03 \times (-24) = 0.32 - 0.72 = -0.40$ です。まだ壁から遠いのに、左へハンドルを切り始めます。
:::

**問3**　速さを1コマで求めると、シミュレータではうまくいかない理由を2つ答えましょう。

:::details 答え
(1) LIDAR の値が1秒に 10 回くらいしか変わらないので、速さがほとんどのコマで 0 になり、ときどき大きなとげになる。(2) 値のばらつきを、とても短い時間（1/60 秒）でわるので、ばらつきが大きく増やされる。
:::
