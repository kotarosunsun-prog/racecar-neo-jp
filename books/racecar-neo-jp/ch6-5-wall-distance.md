6-4 では、真横（90°）の距離を「右の壁までの距離」として表示しました。車が壁とまっすぐ平行に走っているなら、これで正しく測れます。でも、壁沿い走行では、車はハンドルを切って、壁に対して傾きます。この回では、車が傾いていても、壁までの**本当の距離**を求める方法を学びます。

## ① この回でできるようになること

1. 車が傾くと、真横の距離が本当の距離より長くなる理由を説明できる
2. 右側でいちばん近い点を探して、本当の距離を求められる
3. 調べる角度の範囲（窓）の広さを、理由をつけて決められる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Perpendicular distance | 垂直な距離（本当の距離） | 壁に垂直に測った、いちばん短い距離 |
| Ray | 光線 | LIDAR が1つの向きに出して、距離を測る線 |
| Window | 窓 | 調べる角度の範囲。`(45, 135)` なら 45° から 135° まで |
| Tilt | 傾き | 壁の向きに対して、車の向きがずれている角度 |

## ③ 本文

### 真横の距離は、傾くと長くなる

車が壁と平行なら、真横（90°）の光線は、壁にまっすぐ当たります。このときの長さが、壁までの本当の距離です。

車が壁のほうへ傾くと、真横の光線は、壁にななめに当たります。ななめの線は、まっすぐの線より長いので、**本当の距離より長く**測れてしまいます。車が壁から離れる向きに傾いたときも、同じように長くなります。

説明用の簡単なモデルで、壁から 50 cm の所に車を置き、傾きを変えて測ると、次のようになりました。

| 車の傾き | 0° | 10° | 20° | 30° | 40° | 50° |
|---|---|---|---|---|---|---|
| 真横（90°）の距離 | 50.0 | 50.8 | 53.2 | 57.8 | 65.3 | 77.9 |
| いちばん近い点（45°〜135°） | 50.0 | 50.0 | 50.0 | 50.0 | 50.0 | 50.2 |

（単位は cm）

壁沿い走行では、この「長くなりすぎた距離」を見て、車は「壁から遠すぎる」と思い、ますます壁のほうへハンドルを切ってしまいます。

### いちばん近い点が、本当の距離

壁までの本当の距離は、壁に**垂直**に測った距離です。そして、壁の上の点の中で、車からいちばん近いのは、その垂直な線が当たる点です。

そこで、右側のある範囲（**窓**）の中で、**いちばん近い点**を探します。5-3 で学んだ `get_lidar_closest_point()` が使えます。

```python
angle, distance = rc_utils.get_lidar_closest_point(scan, (45, 135))
```

`(45, 135)` は「45° から 135° まで」、つまり真横（90°）を中心に、前後 45° ずつの窓です。返ってくる `distance` が壁までの本当の距離、`angle` がその点の向きです。表のとおり、車が 40° 傾いても、いちばん近い点の距離は 50 cm のままでした。

### 窓の広さの決め方

窓の広さには、次の2つの気持ちがぶつかります。

- **広くしたい**：車が大きく傾いても、垂直な線が窓の中に入るようにしたい。窓が `(45, 135)` なら、傾き 45° までは正しく測れる
- **せまくしたい**：窓が広すぎると、右の壁ではない物（前の壁の角や、後ろの物）を「いちばん近い点」として拾ってしまう

この本では、まず `(45, 135)` を使います。曲がり角で前の壁を拾ってしまう問題は、6-11 からあとで、コースに合わせて考えます。

### やってみよう：2つの方法を比べる

コントローラで車を運転しながら、真横の距離と、いちばん近い点の距離を表示するプログラムです。シミュレータの Lab I のレベルで、車を右の壁に対していろいろな向きにして、2つの値を比べてみましょう。

```python:wall_measure.py
"""
wall_measure.py
右の壁までの距離を、2つの方法で測って比べる。
車は、コントローラで人が運転する（右トリガー：前、左トリガー：後ろ、左スティック：ハンドル）。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

MAX_SPEED = 0.3

ray = 0.0             # 方法1：真横（90°）の距離
closest = 0.0         # 方法2：右側でいちばん近い点の距離
closest_angle = 0.0   # そのいちばん近い点の角度


def start():
    rc.drive.stop()
    print(">> 右の壁に対して、車をいろいろな向きにして、2つの値を比べよう")


def update():
    global ray, closest, closest_angle

    scan = rc.lidar.get_samples()
    ray = rc_utils.get_lidar_average_distance(scan, 90)
    closest_angle, closest = rc_utils.get_lidar_closest_point(scan, (45, 135))

    rt = rc.controller.get_trigger(rc.controller.Trigger.RIGHT)
    lt = rc.controller.get_trigger(rc.controller.Trigger.LEFT)
    speed = (rt - lt) * MAX_SPEED
    angle = rc.controller.get_joystick(rc.controller.Joystick.LEFT)[0]
    rc.drive.set_speed_angle(speed, angle)


def update_slow():
    print(f"真横 {ray:6.1f} cm ｜ いちばん近い点 {closest:6.1f} cm（{closest_angle:5.1f}°）")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

車が壁と平行なときは、2つの値はほとんど同じです。車を壁のほうへ（または壁から離れる向きへ）傾けるほど、真横の値だけが大きくなるはずです。

シミュレータでは、2つの値が平行なときでも少しちがったり、いちばん近い点の角度が、止まっていても 90° のまわりで動いたりします。これは測った値のばらつき（ノイズ）のせいです。次の 6-6 で、このばらつきをくわしく調べます。

## ④ 数式・コード

### 傾きと、真横の距離の関係

本当の距離を $d$、車の傾きを $\theta$ とすると、真横の光線の長さ $r$ は、三角比を使って次のように書けます。

$$
r = \frac{d}{\cos\theta}
$$

$\cos 0° = 1$ なので、傾きがなければ $r = d$ です。$\cos 30° \approx 0.866$ なので、30° 傾くと $r \approx 50 \div 0.866 \approx 57.7$ cm になります。表の 57.8 cm は、`get_lidar_average_distance()` がまわり 4° の点を平均しているぶん、少しだけ長くなっています。

### いちばん近い点の角度から、傾きもわかる

車が壁のほうへ $\theta$ 傾くと、壁に垂直な向きは、真横より $\theta$ だけ前にずれて、$90° - \theta$ になります。つまり、`get_lidar_closest_point()` が返す角度から、車の傾きも求められます。

```python
angle, distance = rc_utils.get_lidar_closest_point(scan, (45, 135))
tilt = 90 - angle     # ＋：壁のほうへ傾いている、－：壁から離れる向き
```

ただし、この傾きはばらつきが大きく、そのままでは使いにくいことがわかります（6-10）。

## ⑤ つまずきポイント

### 窓を `(135, 45)` と書いてしまう

`get_lidar_closest_point()` の窓は、「はじめの角度から、時計回りに、終わりの角度まで」です。`(135, 45)` と書くと、135° から時計回りに 360° をこえて 45° まで、つまり**後ろと左と前**の広い範囲になってしまいます。右側は `(45, 135)` です。

### いちばん近い点が、壁ではない物になる

窓の中に、壁よりも近い物（柱、前の壁の角など）があると、それを拾います。いちばん近い点の角度が、急に大きく変わったときは、壁ではない物を見ている可能性があります。

### 窓の中にデータがない

窓の中がすべて 0.0（データなし）だと、`get_lidar_closest_point()` は、とても大きな距離（約 100 万 cm）を返します（5-3）。このまま壁沿い走行に使うと、「壁から遠すぎる」と思って、大きくハンドルを切ってしまいます。6-6 で、「壁が見えない」ことを見分ける方法を作ります。

## ⑥ 確認問題

**問1**　本当の距離が 40 cm で、車が壁のほうへ 60° 傾いています。真横の光線の長さは何 cm ですか（$\cos 60° = 0.5$）。

:::details 答え
$40 \div 0.5 = 80$ cm です。本当の距離の2倍に測れてしまいます。
:::

**問2**　左の壁までの本当の距離を、いちばん近い点で測るには、窓をどう書けばよいですか。

:::details 答え
`(225, 315)` です。左（270°）を中心に、前後 45° ずつの窓です。
:::

**問3**　`get_lidar_closest_point(scan, (45, 135))` が、角度 80.0 を返しました。車は、壁に対してどちら向きに、何度傾いていますか。

:::details 答え
$90 - 80 = 10$ なので、壁のほうへ 10° 傾いています（ばらつきがなければ）。
:::
