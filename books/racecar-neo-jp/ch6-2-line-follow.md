この回の課題は、オンライン事前コースの **Lab F**「ライントレース（Line Follower）」です。床にはられた色つきの線を、カメラで見ながらたどって走ります。線の位置は 5-2 の輪郭で、ハンドルの角度は 6-1 の比例制御で決めます。

## ① この回でできるようになること

1. カメラ画像の下の部分（車のすぐ前の床）だけを切りとって、線を見つけられる
2. 線の中心が、画面の真ん中から左右にどれだけずれているかを、−1〜1 の数で表せる
3. ずれに比例してハンドルを切り、線の上を走り続けられる
4. 何色もの線があるとき、優先する色を選べる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Line following | ライントレース | 床の線をたどって走ること |
| Crop | 切りとり（クロップ） | 画像の一部だけを取り出すこと |
| Normalize | 正規化 | 値の範囲を −1〜1 のような決まった範囲にそろえること |
| Priority | 優先順位 | いくつも候補があるとき、どれを先に選ぶかの順番 |

## ③ 本文

### 線を見る：車のすぐ前の床だけを切りとる

カメラの画像には、遠くの床や壁、ほかの物も写っています。線をたどるには、**車のすぐ前の床**だけを見れば十分です。そこで、画像の下の部分だけを切りとります。

```python
CROP_FLOOR = ((360, 0), (rc.camera.get_height(), rc.camera.get_width()))
image = rc_utils.crop(image, CROP_FLOOR[0], CROP_FLOOR[1])
```

`rc_utils.crop(画像, 左上, 右下)` は、左上の (行, 列) から、右下の (行, 列) の1つ手前までを切りとります（5-1）。`CROP_FLOOR` は「行 360 から下の、横いっぱい」なので、画像の下の 120 行だけが残ります。

![説明用の簡単なモデルで作ったカメラの画像。床に青い線が右へ曲がりながら続いている。画像の下の、行 360 から 479 の部分をオレンジの点線で囲み、「切りとる部分（車のすぐ前の床）」としている。その中で見つけた線の中心は、列 552 にある。画面の真ん中（列 320）から線の中心までの矢印に、ずれ ＝ (552 − 320) ÷ 320 ＝ +0.72 と書かれている](/images/racecar-neo-jp/6-2/fig1-camera.png)
*図1　カメラで見た床の線と、ずれの求め方（説明用の簡単なモデル）*

切りとった画像の中で、5-2 と同じように、線の色の輪郭を探して、いちばん大きいものの中心を求めます。中心は (行, 列) で返ってきますが、ハンドルに使うのは**列**のほうです。

### ずれを −1〜1 で表す

線の中心の列が、画面の真ん中（列 320）からどれだけ左右にずれているかを、次の式で −1〜1 に**正規化**します。

$$
\text{error} = \frac{\text{列} - 320}{320}
$$

線が真ん中なら 0、右のはし（列 639）なら約 +1、左のはし（列 0）なら −1 です。図1では +0.72 なので、線は右のほうにあります。

### ずれに比例して、ハンドルを切る

線が右にあれば右に、左にあれば左にハンドルを切れば、線が画面の真ん中にもどってきます。6-1 の比例制御そのものです。

$$
\text{angle} = K_P \times \text{error}
$$

ずれを −1〜1 にそろえてあるので、$K_P = 1$ なら「線が画面のはしにあるとき、ハンドルをいっぱいに切る」という意味になります。

```python:line_follow.py
"""
line_follow.py
床の青い線の中心がカメラ画像の真ん中に来るように、比例制御でハンドルを切る。
速さは右トリガー（前）と左トリガー（後ろ）で、人が決める。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

BLUE = ((90, 50, 50), (120, 255, 255))   # 線の色（Lab E・Lab F のひな形の青）
MIN_CONTOUR_AREA = 30                      # これより小さいかたまりは無視する
CROP_FLOOR = ((360, 0), (rc.camera.get_height(), rc.camera.get_width()))   # 画像の下の部分（車のすぐ前の床）
MAX_SPEED = 0.5                            # トリガーを全部押したときの speed
KP = 1.0                                   # 比例ゲイン（走らせながら調整する）

angle = 0.0   # 今のハンドルの角度（線が見えないときは、前の角度を使い続ける）


def get_line_error():
    """線の中心が、画面の真ん中から左右にどれだけずれているか（左はし -1 〜 右はし +1）。見えなければ None"""
    image = rc.camera.get_color_image()
    if image is None:
        return None
    image = rc_utils.crop(image, CROP_FLOOR[0], CROP_FLOOR[1])
    contours = rc_utils.find_contours(image, BLUE[0], BLUE[1])
    contour = rc_utils.get_largest_contour(contours, MIN_CONTOUR_AREA)
    if contour is None:
        return None
    center = rc_utils.get_contour_center(contour)      # (行, 列)。行は切りとった画像の中での位置
    half = rc.camera.get_width() / 2
    return (center[1] - half) / half


def start():
    global angle
    angle = 0.0
    rc.drive.stop()
    print(">> 右トリガーで前へ。ハンドルは、線を見て自動で切ります")


def update():
    global angle

    error = get_line_error()
    if error is not None:
        angle = rc_utils.clamp(KP * error, -1.0, 1.0)   # ずれに比例してハンドルを切る

    rt = rc.controller.get_trigger(rc.controller.Trigger.RIGHT)
    lt = rc.controller.get_trigger(rc.controller.Trigger.LEFT)
    speed = (rt - lt) * MAX_SPEED

    rc.drive.set_speed_angle(speed, angle)


if __name__ == "__main__":
    rc.set_start_update(start, update)
    rc.go()
```

線が見えなくなったとき（`error` が `None`）は、`angle` を変えずに、前のコマの角度を使い続けます。カーブで線が画面の外に出ても、同じ向きに曲がり続けるので、線をまた見つけやすくなります。

### KP の大きさと、カーブ

![説明用の簡単なモデルで、線の 8 cm 右から speed 0.5 で走らせた道すじ。線はまっすぐ 150 cm 進んでから、半径 150 cm で右に 90 度曲がる。KP = 0.3（オレンジ）は、カーブで曲がりきれず、線から大きく外れて左上へ行ってしまう。KP = 1.0（緑）は、カーブで少し外側にふくらむが、線をたどりきる。KP = 3.0（紫）は、ほぼ線の上をたどる](/images/racecar-neo-jp/6-2/fig2-paths.png)
*図2　KP をかえて線をたどった道すじ（説明用の簡単なモデル）*

- **KP が小さすぎる**（0.3）：線が画面のはしにあっても、ハンドルを少ししか切らない。カーブで曲がりきれず、線を見失う
- **KP を大きくする**（1.0、3.0）：線から少しずれただけで大きくハンドルを切るので、線にぴったりついていける

ただし、KP を大きくしすぎたり、速く走ったりすると、今度は線の左右を行ったり来たりする**ふらつき**が出てきます。ふらつきの理由と対策は、6-8 と 6-9 で、壁沿い走行を例にくわしく学びます。

### Lab F をやってみよう

課題のファイルは、labs フォルダの中の `lab_f/lab_f.py` です。課題のゴールは次のとおりです（原典の Expected Outcome より）。

- 右トリガーで全開で前へ、左トリガーで全開で後ろへ進む
- ハンドルの角度は、線の輪郭の中心だけで決める
- 線の色は、**赤 → 緑 → 青**の順に優先する

シミュレータのレベルは、**Neo Labs** の **Lab F: Line Follower** です。探索モードでは、Tab キーで次のチェックポイントに進めます。まちがった道に進むと、チェックポイントにもどされます。自動採点モードでは、次のコースを順番に走り、ゴールまでたどりつけば完了です。

| 順番 | コース | 内容 | 制限時間 |
|---|---|---|---|
| 1 | Gentle Turn | 赤い線の、ゆるやかな（30°の）カーブ | 10秒 |
| 2 | Sharp Turn | 青い線の、急な（90°の）カーブ | 10秒 |
| 3 | Curved path | 緑の、曲がりくねった線 | 10秒 |
| 4 | Color Priority 1 | 赤 ＞ 緑 ＞ 青 の優先順位で線を選ぶ | 10秒 |
| 5 | Color Priority 2 | 同じ優先順位の、もっと複雑なコース | 20秒 |
| 6 | Challenge: Perpendicular | 車の真横に交わる線を見つけて、そちらに曲がる | ― |

:::message
Lab F は自動採点つきの課題なので、この本では、緑と赤の色の範囲などの答えの数値は載せません。
:::

- **Part 1：緑と赤の色の範囲**。5-1 の `hsv_probe.py` で、シミュレータの線の色を測って決めます。赤は H が 0 と 179 をまたぎます（5-1）
- **切りとり**：`rc_utils.crop(image, _____, _____)` の2つの空欄には、上の `CROP_FLOOR` の左上と右下を入れます
- **Part 2：線を探す**。ひな形には、優先順位の順に色を並べた `COLOR_PRIORITY = (RED, GREEN, BLUE)` が用意されています。5-2 では「いちばん面積の大きい色」を選びましたが、ここでは**優先順位の高い色から順に調べて、はじめに見つかった色**を使います。`for` で1つずつ調べ、見つかったら `break` でぬけ出すと書けます
- **Part 3：角度を決める**。上の `line_follow.py` と同じ考え方です。`contour_center` の2つめ（列）を使います

:::message alert
**訳注：ひな形の食い違い**
原典のひな形の `start()` で表示される文字は「Lab 2A - Color Image Line Following」になっていますが、これは古い課題の名前です。今の課題名は Lab F です。
:::

## ④ 数式・コード

### remap_range を使った書き方

列の値 0〜640 を、−1〜1 にそろえる計算は、`rc_utils.remap_range()` でも書けます。

```python
error = rc_utils.remap_range(center[1], 0, rc.camera.get_width(), -1.0, 1.0)
```

「列が 0 なら −1、640 なら 1」になるように、まっすぐな関係でつなぐ、という意味です。上の式と同じ結果になります。

### 切りとる場所と、先の見え方

切りとる場所を画像の上のほうにすると、**より遠くの床**を見ることになります。遠くを見ると、カーブに早く気づけますが、今の車の位置とのずれはわかりにくくなります。近くを見ると、今のずれは正確にわかりますが、カーブに気づくのが遅れます。どこを見るかも、調整できる大事な設計です（6-15 で、壁沿い走行について考えます）。

図1のモデルでは、カメラを床から 20 cm の高さに、少し下向きに付けています。このとき、行 360 は車の約 29 cm 先、行 479 は約 19 cm 先の床にあたります。

## ⑤ つまずきポイント

### 線と反対の向きにハンドルを切ってしまう

ずれの符号を確かめましょう。線が右にある（列が 320 より大きい）ときに、`angle` がプラス（右）になれば正しい向きです。

### カーブで線を見失う

KP が小さすぎて曲がりきれないか、速すぎるかのどちらかです。KP を大きくするか、速さを下げます。線が見えなくなったときに前の角度を使い続けるのも、効果があります。

### 切りとった画像の行の番号が、もとの画像と合わない

`crop()` で切りとったあとの画像では、行の番号は、切りとった部分の上から数え直しになります。行 360 から切りとったなら、切りとった画像の行 0 は、もとの画像の行 360 です。列の番号は、横いっぱいを残しているので変わりません。

### ほかの色の物に反応してしまう

切りとる範囲を狭くするか、`MIN_CONTOUR_AREA` を大きくします。色の範囲がゆるすぎないかも、5-1 のマスクで確かめましょう。

## ⑥ 確認問題

**問1**　線の中心の列が 160 でした。ずれ（−1〜1）と、`KP = 1.0` のときの `angle` を求めましょう。車はどちらに曲がりますか。

:::details 答え
$\frac{160 - 320}{320} = -0.5$ です。`angle` は $-0.5$ で、左に曲がります。線が画面の左側にあるからです。
:::

**問2**　赤 → 緑 → 青の優先順位のとき、画面に緑の線（面積 3000）と赤の線（面積 200）が見えています。どちらの線をたどりますか。

:::details 答え
赤の線です。面積の大きさではなく、優先順位で選ぶからです（赤の面積が `MIN_CONTOUR_AREA` より大きい場合）。
:::

**問3**　線が見えなくなったとき、`angle` を 0（まっすぐ）にするのと、前の角度を使い続けるのとでは、カーブでどちらがよいと考えられますか。

:::details 答え
前の角度を使い続けるほうがよいと考えられます。カーブで線が画面の外に出たとき、まっすぐにすると線からさらに離れてしまいますが、同じ向きに曲がり続ければ、線をまた見つけやすいからです。
:::
