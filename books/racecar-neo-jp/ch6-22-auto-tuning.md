6-14 では、走らせては直す、をくり返して、手でゲインを決めました。この回では、5-8 で学んだ**勾配降下法**を使って、ゲインを**コンピュータに探させます**。そのために、「走りのよしあし」を1つの数（損失）で表し、ゲインを少しずつ動かして、損失が下がる向きを探します。

## ① この回でできるようになること

1. 走りのよしあしを、1つの数（損失）で表せる
2. 式で傾きを求められないときに、「少しだけ動かす」方法で傾きを求められる
3. 勾配降下法で、PID のゲインを自動で調整するプログラムを動かせる
4. 自動で見つけた値を、そのまま信じてはいけない理由を説明できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Cost function | 損失関数（評価関数） | よしあしを1つの数で表す式。小さいほどよい |
| Finite difference | 差分 | 値を少しだけ動かしたときの変化から、傾きを求める方法 |
| Gradient descent | 勾配降下法 | 傾きと反対の向きに少しずつ動かして、損失を小さくする方法（5-8） |
| Model | モデル | 本物のかわりに、計算で動きをまねるもの |
| Local minimum | 局所的な最小 | まわりよりは低いが、いちばん低いとは限らない谷底 |

## ③ 本文

### 何を「よい」とするかを、数で決める

勾配降下法を使うには、5-8 と同じように、**損失**が必要です。5-8 では、直線とデータのずれの2乗の平均でした。壁沿い走行では、次の2つを足したものにします。

- **壁からの距離のずれの2乗**：目標の 50 cm から離れているほど、大きくなります。早く目標に近づき、行き過ぎないほど小さくなります
- **ハンドルの切りすぎの罰**：angle の2乗に、重み `EFFORT` をかけたものです。ハンドルを大きく、せわしなく切るほど、大きくなります

これを、走っている間の毎コマで足して、コマ数で割ります（平均）。2つめがないと、「どんなに激しくハンドルを切ってもよいから、早く目標に近づけ」という意味になってしまいます（あとで確かめます）。

### 本物のかわりに、モデルで走らせる

損失を1回求めるには、1回走らせる必要があります。勾配降下法では、これを何百回もくり返します。シミュレータで、手で何百回もスタートボタンを押すのは大変です。

そこで、車と壁の動きを計算でまねる、とても簡単な**モデル**をプログラムの中に書きます。

- 車は、決まった速さ（75 cm/秒、speed 0.5 くらい）で進む
- 壁の向き $\alpha$ だけ傾いて進むと、壁までの距離が変わる（6-10 の「ずれの変わる速さ $= v \sin\alpha$」）
- ハンドルを切ると、向きが変わる。タイヤは、命令の角度に少し遅れて近づく
- LIDAR の値は、0.1 秒に1回しか変わらない（6-8）

モデルは1秒もかからずに 8 秒分を走らせられるので、何百回でもくり返せます。

### 傾きは、少しだけ動かして求める

5-8 では、損失の傾きを式で求めました。でも、車を走らせて求める損失は、式で傾きを求められません。そこで、5-8 で確かめに使った「**少しだけ動かしてみる**」方法を使います。

$$
\frac{\partial L}{\partial K_P} \approx \frac{L(K_P + h,\ K_A) - L(K_P - h,\ K_A)}{2h}
$$

5-8 では、片側（$+h$）だけに動かしましたが、ここでは両側に動かして差をとります。このほうが、傾きを正確に求められます。KA についても同じです。

### やってみよう：ゲインを自動で探す

このプログラムは、シミュレータを使いません。ふつうの Python で動きます。

```python:auto_tune.py
"""
auto_tune.py
壁沿い走行のゲイン（KP と、壁の向きのゲイン KA）を、勾配降下法で自動で探す（6-22）。
車と壁は、この中に書いた簡単なモデルで計算する（シミュレータは使わない）。
"""

import math

# ---- 車と壁のモデル（説明用の簡単なモデル）----
DT = 1 / 60          # 1コマの時間（秒）
V = 75.0             # 車の速さ（cm/秒）。speed 0.5 くらい
WHEELBASE = 30.0     # 前輪と後輪の間の長さ（cm）
MAX_STEER = math.radians(20)   # angle = 1 のときのタイヤの角度
STEER_LAG = 0.08     # タイヤが命令の角度に近づくまでの時間（秒）
MEASURE_EVERY = 6    # LIDAR の値が変わるのは、6コマ（0.1 秒）に1回
TARGET = 50.0        # 右の壁から保ちたい距離（cm）
START = 100.0        # はじめの距離（cm）
SECONDS = 8.0        # 走らせる時間（秒）
EFFORT = 20.0        # ハンドルを大きく切ることへの「罰」の重さ


def run(kp, ka):
    """ゲイン (kp, ka) で走らせて、(損失, 距離の記録) を返す"""
    d, alpha, steer = START, 0.0, 0.0     # 壁までの距離、壁の向き（ラジアン）、タイヤの角度
    seen_d, seen_alpha = d, alpha         # LIDAR で測った値（ときどきしか変わらない）
    total = 0.0
    history = []
    frames = int(SECONDS / DT)
    for f in range(frames):
        if f % MEASURE_EVERY == 0:
            seen_d, seen_alpha = d, alpha
        angle = kp * (seen_d - TARGET) + ka * math.degrees(seen_alpha)
        angle = max(-1.0, min(1.0, angle))
        # 車を1コマ動かす
        steer += (angle * MAX_STEER - steer) / STEER_LAG * DT
        alpha -= V / WHEELBASE * math.tan(steer) * DT
        d += V * math.sin(alpha) * DT
        # 損失：ずれの2乗 ＋ ハンドルの切りすぎの罰
        total += ((d - TARGET) / 10) ** 2 + EFFORT * angle ** 2
        history.append(d)
        if d < 12:                        # 壁にぶつかった
            return total / frames + 1000.0, history
    return total / frames, history


def loss(kp, ka):
    return run(kp, ka)[0]


# ---- 勾配降下法（5-8）----
LR = 0.00002         # 学習率
H = 0.0001           # 傾きを求めるために、少しだけ動かす量
kp, ka = 0.01, 0.01  # はじめの値（小さめ）

for step in range(301):
    L = loss(kp, ka)
    # 少しだけ動かして、傾きを求める（両側に動かして、差をとる）
    grad_kp = (loss(kp + H, ka) - loss(kp - H, ka)) / (2 * H)
    grad_ka = (loss(kp, ka + H) - loss(kp, ka - H)) / (2 * H)
    if step in (0, 1, 2, 5, 10, 20, 50, 100, 200, 300):
        print(f"{step:3d} 回め：KP = {kp:.4f}, KA = {ka:.4f}, 損失 = {L:.3f}")
    kp = kp - LR * grad_kp           # 傾きと反対向きに、少し動かす
    ka = ka - LR * grad_ka
```

## ④ 数式・コード

### モデルの式

1コマ（$\Delta t = 1/60$ 秒）ごとに、次のように計算しています。$v$ は速さ、$W$ は前輪と後輪の間の長さ（30 cm）、$\delta$ はタイヤの角度です。

$$
\alpha \leftarrow \alpha - \frac{v}{W} \tan\delta \,\Delta t, \qquad d \leftarrow d + v \sin\alpha \,\Delta t
$$

1つめは、ハンドルを右に切る（$\delta > 0$）と、向き $\alpha$ が壁のほうへ回ることを、2つめは、6-10 の「ずれの変わる速さ $v \sin\alpha$」を表しています。タイヤの角度は、命令の角度に、0.08 秒ほどで近づきます。

$$
\delta \leftarrow \delta + \frac{\delta_{\text{命令}} - \delta}{0.08}\,\Delta t
$$

### 損失の式

$N$ コマ走らせたときの損失は、次のとおりです。ずれは 10 cm を 1 として数えています。

$$
L = \frac{1}{N} \sum_{i=1}^{N} \left\{ \left( \frac{d_i - 50}{10} \right)^2 + \text{EFFORT} \times \text{angle}_i^{\,2} \right\}
$$

### 両側に動かすと、なぜ正確なのか

片側だけに動かす $\dfrac{L(K+h) - L(K)}{h}$ は、$K$ と $K + h$ の間の平均の傾きなので、本当は $K + \dfrac{h}{2}$ の所の傾きに近い値になります。両側に動かす $\dfrac{L(K+h) - L(K-h)}{2h}$ は、ちょうど $K$ を真ん中にはさむので、$K$ の所の傾きにより近くなります。そのかわり、損失を1回多く計算します。

### パラメータが多いとき

この方法では、パラメータ1つにつき、損失を2回計算します。KP、KI、KD の3つなら6回、ゲインの数が増えるほど時間がかかります。5-10 の誤差逆伝播のように、傾きを式で求められれば速いのですが、車を走らせる計算は、ふつうは式で微分できません。そのため、ゲインの自動調整には、勾配を使わずに、よさそうな所をかしこく選んで試していく方法（ベイズ最適化など）も使われます。

## ⑤ つまずきポイント

### 損失がどんどん大きくなる

学習率が大きすぎます（5-8）。ゲインのように小さな数を動かすときは、傾きが何百にもなることがあるので、学習率はとても小さく（この回では 0.00002）します。1回めに、ゲインがどれだけ動いたかを見て決めましょう。

### ゲインがマイナスになった

1歩が大きすぎて、谷を飛びこえています。学習率を小さくするか、はじめの値を変えましょう。「ゲインは 0 より大きい」とわかっているなら、`max(kp, 0.0)` のように、動かしたあとで下限をつけておくのも1つの方法です。

### モデルでは速いのに、シミュレータではふらつく

モデルにない遅れやばらつきがあるからです。モデルの `MEASURE_EVERY`（LIDAR の値が変わる間隔）や `STEER_LAG`（タイヤの遅れ）を大きくして探し直すと、少し控えめなゲインになります（たとえば `STEER_LAG` を 0.2 にすると、KP 0.0167、KA 0.0310）。モデルを本物に近づけるほど、見つかる値も本物に合うようになります。

## ⑥ 確認問題

**問1**　ある点で、KP を $+0.0001$ 動かすと損失が 4.0120、$-0.0001$ 動かすと 4.0100 でした。両側に動かす方法で求めた、KP についての傾きはいくつですか。

:::details 答え
$(4.0120 - 4.0100) \div (2 \times 0.0001) = 10$ です。
:::

**問2**　問1の点で、学習率が 0.00002 なら、KP はどちらに、どれだけ動きますか。

:::details 答え
傾きと反対の向きに、$0.00002 \times 10 = 0.0002$ 動きます。傾きがプラスなので、KP を 0.0002 **減らします**。
:::

**問3**　損失を「ずれの2乗の平均」だけにして、ハンドルの罰を入れないと、どんなゲインが見つかりやすくなりますか。

:::details 答え
KP も KA も大きい、ハンドルを強く、せわしなく切るゲインです。この回では、300 回めでも大きくなり続けていました。実物の車では、ハンドルの激しい動きは、ふらつきや、部品の傷みにつながります。
:::
