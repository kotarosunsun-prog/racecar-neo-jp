6-5 で、右側でいちばん近い点を探せば、車が傾いていても壁までの本当の距離がわかることを学びました。でも、実際の LIDAR の値には、**ばらつき**があり、**データのぬけ**があり、壁には**すき間**もあります。この回では、そうしたデータからでも、安定した距離を求める関数を作ります。この関数は、6-7 からの壁沿い走行の「目」になります。

## ① この回でできるようになること

1. LIDAR の値が乱れる3つの原因（ばらつき・ぬけ・すき間）を説明できる
2. いちばん近い点だけを使うと、距離が短めに出る理由を説明できる
3. いちばん近い点のまわりの「近い点だけ」を平均して、安定した距離を求められる
4. 壁が見えないときに `None` を返して、見分けられるようにできる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Noise | ノイズ（ばらつき） | 同じ物を測っても、毎回少しずつ違う値が出ること |
| Outlier | 外れ値 | ほかの値から大きく外れた値 |
| Dropout | データのぬけ | 測れなかった点。RACECAR の LIDAR では 0.0 になる |
| Moving average | 移動平均 | 最近のいくつかの値をならして、ばらつきを小さくする方法 |

## ③ 本文

### LIDAR の値が乱れる3つの原因

**ばらつき（ノイズ）**：シミュレータの設定にある **Realism** は、はじめからオンになっていて、すべてのセンサに本物らしい誤差を加えます。LIDAR には、距離のおよそ 2% のばらつきが加わります（原典のコメントによると、YDLIDAR X4 というセンサの資料にもとづく値です）。50 cm の壁なら、1 cm くらいずつ、測るたびに値が変わります。

**データのぬけ**：近すぎる物（12 cm より近い）や、遠すぎる物（10 m より遠い）は測れず、0.0 になります。

**すき間**：壁には、入り口や曲がり角があります。Lab I の Posts のコースのように、壁のかわりに柱が並んでいることもあります。すき間の向きの光線は、奥の物まで届いてしまいます。

もう1つ、知っておきたいことがあります。シミュレータの LIDAR は、**1秒に6回転**しながら測ります。プログラムは1秒に 60 コマ動くので、1コマの間に新しくなるのは、1回転の 10 分の 1 だけです。ある向きの値は、1秒に6回しか新しくならず、その間は同じ値のままです。このことは、6-8 と 6-9 で大事になります。

### 4つの測り方をくらべる

わかることは、次の3つです。

1. **平均すると、ばらつきが小さくなる**。真横の1点のばらつき 1.1 cm が、まわり 4° の9点の平均では 0.4 cm になった
2. **真横だけを見ると、すき間で奥まで測ってしまう**。入り口では 250 cm、柱のすき間では 200 cm に、ほかの値から大きく外れた値（**外れ値**）が出る。壁沿い走行なら、車は「壁から遠すぎる」と思って、すき間に飛びこんでしまう
3. **いちばん近い点は、すき間に強いが、短めに出る**。壁の所でも、平均が 48.0 cm と、本当の 50 cm より 2 cm も短い

### いちばん近い点が短めに出るわけ

いちばん近い点のまわりには、ほとんど同じ距離の点が何十個もあります。どの点にも ±1 cm くらいのばらつきがあるので、その中には、たまたま短めに出た点がいくつかあります。「いちばん近い点」を選ぶと、**たまたまいちばん短く出た点**を選ぶことになります。だから、いつも少し短めになるのです。

### 近い点だけを平均する

そこで、2つの方法のよいところを組み合わせます。

1. 右側（45°〜135°）で、いちばん近い点を探す。これで、壁のある向きがわかる
2. その点のまわり ±5°（21個）の値のうち、**いちばん近い点に近いものだけ**を平均する

2 で「近いものだけ」にするのは、すき間の奥の物や、0.0（データなし）を平均に入れないためです。この本では、「いちばん近い点 + 5 cm より近い」点だけを使います。

```python
MAX_WALL = 300.0    # これより遠いときは「壁なし」とみなす


def right_wall_distance(scan):
    """右の壁までの距離（cm）。壁が見つからなければ None"""
    closest_angle, closest = rc_utils.get_lidar_closest_point(scan, (45, 135))
    if closest > MAX_WALL:                             # 窓の中に壁がない
        return None
    center = round(closest_angle * len(scan) / 360)    # いちばん近い点の番号
    near = []
    for d in scan[center - 10 : center + 11]:          # そのまわり ±5°（21個）
        if 0 < d < closest + 5:                        # 0.0（データなし）と、奥の物を除く
            near.append(d)
    return sum(near) / len(near)                       # 近い点だけの平均
```

- `closest > MAX_WALL`：窓の中に壁がないときは、`get_lidar_closest_point()` が約 100 万 cm を返します（6-5）。300 cm より遠いときは「壁なし」として `None` を返します。使う側は `if distance is None:` で見分けられます
- `round(closest_angle * len(scan) / 360)`：角度を、`scan` の番号にもどしています（5-3）。0.5° ごとなので、±5° は ±10 番です
- `near` には、いちばん近い点そのものが必ず入るので、空になることはありません

表のとおり、この方法は、壁の所では 50.1 cm と短めにならず、入り口や柱の所でも大きくはね上がりませんでした。入り口のまん中で 72 cm くらいまで大きくなるのは、いちばん近い物が、入り口の角になるからです。柱の所で 57 cm くらいまで大きくなるのも、柱と柱の間では、いちばん近い柱が、ななめ前やななめ後ろにあるからです。

## ④ 数式・コード

### 時間でならす（指数移動平均）

ここまでは、1回の `scan` の中で、となりの点どうしを平均しました。もう1つの方法は、**時間**でならす方法です。前のコマまでにならした値 $\bar{d}$ に、新しく測った値 $d$ を少しずつ混ぜていきます。

$$
\bar{d} \leftarrow \bar{d} + \alpha \, (d - \bar{d})
$$

$\alpha$ は 0〜1 の数で、小さいほど、よくならされます。5-5 の相補フィルタと似た形です。

```python
ALPHA = 0.2
smooth = None

def update():
    global smooth
    d = right_wall_distance(rc.lidar.get_samples())
    if d is not None:
        if smooth is None:
            smooth = d                        # 最初の1回は、そのまま使う
        else:
            smooth += ALPHA * (d - smooth)    # 新しい値を 2 割だけ混ぜる
```

ただし、時間でならすと、**遅れ**が生まれます。車が本当に壁に近づいても、ならした値はゆっくりとしか変わりません。6-8 で見るように、遅れは壁沿い走行のふらつきを大きくします。この本では、まずは1回の `scan` の中でならす方法だけを使います。

### 平均すると、ばらつきが小さくなる

ばらつきが同じくらいで、たがいに関係のない $n$ 個の値を平均すると、ばらつき（標準偏差）は、およそ $\dfrac{1}{\sqrt{n}}$ 倍になります。9個なら $\dfrac{1}{3}$ 倍です。表でも、1.1 cm が 0.4 cm になりました。

## ⑤ つまずきポイント

### 広い通路で「壁が見えない」になる

`MAX_WALL` より遠い壁は「壁なし」になります。とても広い通路を走るときは、`MAX_WALL` を大きくします。ただし、大きくしすぎると、遠くの関係ない物を壁と思ってしまいます。

### `None` のまま計算して、エラーになる

`right_wall_distance()` は `None` を返すことがあります。`distance - TARGET` のように、`None` のまま計算すると `TypeError` になります。使う前に、かならず `if distance is None:` で確かめましょう。

### 正面や後ろの窓で使うと、うまく動かない

この関数は、右側の窓 `(45, 135)` 用です。0° をまたぐ窓（正面など）に変えると、`center - 10` が負の数になり、`scan[center - 10 : center + 11]` が、思った範囲を取り出しません。左の壁なら、窓を `(225, 315)` に変えるだけで使えます。

## ⑥ 確認問題

**問1**　いちばん近い点を使うと、すき間に強いのはなぜですか。

:::details 答え
すき間の向きの光線は奥の物まで届いて長くなりますが、いちばん近い点を選ぶと、長い値は選ばれないからです。
:::

**問2**　`get_lidar_closest_point(scan, (45, 135))` が `(87.5, 48.3)` を返しました。`right_wall_distance()` の中の `center` はいくつですか。

:::details 答え
$87.5 \times 720 \div 360 = 175$ です。`scan[165:186]` の 21 個を調べます。
:::

**問3**　問2 のとき、`scan[165:186]` の中に 0.0 と 201.4 と 49.6 がありました。平均に入るのはどれですか。

:::details 答え
49.6 だけです。0.0 は「データなし」、201.4 は $48.3 + 5 = 53.3$ より遠いので入りません。
:::
