5-2 では、「H が 90〜120 なら青」のようなルールを、人が考えて書きました。色の箱ならこれで見分けられますが、コーンや人、道路標識となると、ルールを書ききるのはとても難しくなります。この回から 5-10 までは、ルールを人が書くかわりに、**データからルールを見つけさせる**「機械学習」のしくみを学びます。5-11 からは、それを使って、実機のカメラで物を見つけるところまで進みます。

## ① この回でできるようになること

1. 「ルールを書く」やり方と、「データから学ぶ」やり方の違いを説明できる
2. 教師あり学習の言葉（入力・正解・モデル・学習・推論）を使って、しくみを説明できる
3. いちばん簡単な機械学習として、しきい値をデータから選べる
4. データを学習用とテスト用に分ける理由を説明できる

## ③ 本文

### ルールを書くやり方と、データから学ぶやり方

![上は、これまでのやり方。人が考えたルール「H が 90〜120 なら青」を、プログラムにそのまま書き、答え「これは青」を出す。色の箱なら書けるが、コーンや人や止まれの標識のルールは書ききれない。下は機械学習。入力とその正解の組（写真と「これはコーン」）をたくさん用意し、間違いが少なくなるようにモデルの数を調整する（学習）。学習したモデルは、見たことのない入力にも答えを出す（推論）。人が書くのは「どう学ぶか」までで、「どう見分けるか」はデータから見つける](/images/racecar-neo-jp/5-6/fig1-rule-vs-ml.png)
*図1　ルールを書くやり方と、機械学習*

機械学習では、人は「見分け方」を直接書きません。そのかわりに、次の3つを用意します。

1. **データ**：入力と、その正解の組をたくさん
2. **モデル**：入力から答えを出す計算のしかた。中に、あとで決める数（**パラメータ**）を持っている
3. **学び方**：「答えがどれだけ間違っているか」を測り、間違いが少なくなるようにパラメータを変える手順

こうして正解つきの例から学ぶ方法を、先生（正解）がいる学び方にたとえて、**教師あり学習**といいます。

### 分類と回帰

教師あり学習で答えるものには、大きく2種類あります。

| 種類 | 答えの形 | RACECAR での例 |
|---|---|---|
| 分類 | どのグループか | この箱は、緑か青か／この写真に写っているのはコーンか人か |
| 回帰 | 数の大きさ | アクセルをこれだけ踏むと、何 m/s で走るか |

5-11 で学ぶ**物体検出**は、「何が写っているか（分類）」と「どこに写っているか（枠の位置という数、回帰）」の両方を答えます。

### いちばん小さな機械学習：しきい値をデータから選ぶ

緑の箱と青の箱を、色合い H だけで見分けることにします。いろいろな明るさや向きで測った H の値と、「緑か青か」の正解が、それぞれ60個ずつあるとします。

- **モデル**：「H がしきい値 $t$ より大きければ青、そうでなければ緑」と答える
- **パラメータ**：しきい値 $t$
- **学び方**：$t$ を 0 から 179 まで全部ためし、学習用データでいちばんよく当たるものを選ぶ

```python:learn_threshold.py
"""
learn_threshold.py
色合い H の値から「緑の箱か、青の箱か」を見分けるしきい値を、データから選ぶ。
"""

import numpy as np

# 作ったデータ：いろいろな明るさ・向きで測った H の値（0 = 緑、1 = 青 が正解）
rng = np.random.default_rng(4)
h_green = rng.normal(72, 9, 60)      # 緑の箱の H
h_blue = rng.normal(100, 9, 60)      # 青の箱の H
h = np.concatenate([h_green, h_blue])
label = np.concatenate([np.zeros(60), np.ones(60)])

# 学習用とテスト用に分ける（まぜてから、4分の3を学習用に）
order = rng.permutation(len(h))
train, test = order[:90], order[90:]


def accuracy(threshold, idx):
    """しきい値より大きければ「青」と答えたときの正解率"""
    guess = (h[idx] > threshold).astype(float)
    return np.mean(guess == label[idx])


# 学習：0〜179 のしきい値をすべて試し、学習用データでいちばん正解率が高いものを選ぶ
best = max(range(180), key=lambda t: accuracy(t, train))

print(f"選んだしきい値：H > {best} なら青")
print(f"学習用データの正解率：{accuracy(best, train):.1%}")
print(f"テスト用データの正解率：{accuracy(best, test):.1%}")
```

```text
選んだしきい値：H > 87 なら青
学習用データの正解率：96.7%
テスト用データの正解率：86.7%
```

*図2　学習用データの H の分布と、データから選んだしきい値（作ったデータ）*

人が「だいたいこのへん」と決めるかわりに、コンピュータが、データにいちばん合うしきい値を選びました。とても小さいですが、これも「データから学ぶ」の一例です。

### なぜ、テスト用データを分けておくのか

上の結果では、学習用データの正解率は 96.7% でしたが、テスト用データでは 86.7% に下がりました。

学習用データの正解率は、「練習問題の点数」のようなものです。モデルは練習問題に合わせて作られているので、点数が高く出がちです。本当に知りたいのは、**見たことのない問題**の点数です。そのために、学習に使わないデータ（テスト用データ）を、最初に取り分けておきます。

極端な例として、「学習用データの H と正解を、全部覚えておく」モデルを考えます。学習用データなら 100% 当たりますが、少しでも違う H が来たら、答えられません。このように、学習用データに合わせすぎて、新しいデータに弱くなることを**過学習**といいます。テスト用データの点数を見れば、過学習に気づけます。

:::message
5-14 で使う物体検出の学習では、データを**学習用・検証用・テスト用**の3つに分けます。検証用データは、学習の途中で「うまく進んでいるか」を確かめるのに使います。テスト用データは、最後に1回だけ使って、できばえを確かめます。
:::

### 機械学習がうまくいくための条件

モデルは、データに入っていることしか学べません。

- **量**：少なすぎると、たまたまのくせを学んでしまう
- **ばらつき**：明るい部屋の写真だけで学ぶと、暗い部屋では見分けられない。実際に使う場面のいろいろな条件を入れる
- **正解の正しさ**：正解ラベルが間違っていると、間違いも学んでしまう

5-12 と 5-13 で、自分でデータを集めて正解を付けるときにも、この3つが大事になります。

### この先の地図

| 回 | 学ぶこと |
|---|---|
| 5-7 | 「どれだけ間違っているか」を1つの数（損失）で表す |
| 5-8 | 損失が小さくなる方向へ、パラメータを少しずつ動かす（勾配降下法） |
| 5-9 | たくさんのパラメータを持つモデル（ニューラルネットワーク） |
| 5-10 | たくさんのパラメータの「動かす方向」を、まとめて求める（誤差逆伝播） |
| 5-11〜5-14 | 物体検出のしくみと、データ集め・正解付け・学習・実機での利用 |

この回のしきい値は、0〜179 を全部ためせば選べました。パラメータが何百万個もある大きなモデルでは、全部ためすことはできません。そこで 5-8 の方法を使います。

## ④ 数式・コード

### 正解率

分類のできばえは、まず**正解率**で表します。

$$
\text{正解率} = \frac{\text{正しく答えた数}}{\text{全体の数}}
$$

`learn_threshold.py` の `np.mean(guess == label[idx])` は、「答えと正解が同じなら True（1）、違えば False（0）」を並べて平均しているので、正解率そのものです。

### 学習を、式で書くと

しきい値 $t$ のときの学習用データの正解率を $A(t)$ とすると、この回の学習は、次のように書けます。

$$
t^{*} = \underset{t}{\operatorname{argmax}}\ A(t)
$$

$\operatorname{argmax}$ は「いちばん大きくする $t$ を選ぶ」という意味です。5-7 からは、正解率のかわりに「間違いの大きさ（損失）」を使い、それを**いちばん小さくする**パラメータを選びます（$\operatorname{argmin}$）。

## ⑤ つまずきポイント

### 学習用データで測った点数を、そのまま信じてしまう

学習に使ったデータで測ると、点数は高く出がちです。できばえは、学習に使っていないテスト用データで測りましょう。

### テスト用データを見ながら、何度も調整してしまう

テスト用データの点数を見て、何度も設定を変えていると、だんだんテスト用データに合わせた調整になってしまいます。調整には検証用データを使い、テスト用データは最後の確認に取っておきます。

### 分け方がかたよっている

たとえば、写真を撮った順に前半を学習用、後半をテスト用にすると、「前半は明るい部屋、後半は暗い部屋」のようにかたよることがあります。`learn_threshold.py` のように、**まぜてから**分けます。

## ⑥ 確認問題

**問1**　次のうち、回帰で答えるものはどれですか。
(1) カメラに写っているのが、コーンか、人か
(2) LIDAR の値から、あと何秒で壁にぶつかるか
(3) 信号の色が、赤か、青か

:::details 答え
(2) です。「何秒」という数の大きさを答えるので回帰です。(1) と (3) は、どのグループかを答える分類です。
:::

**問2**　学習用データの正解率が 99%、テスト用データの正解率が 70% でした。何が起きていると考えられますか。

:::details 答え
過学習が起きていると考えられます。学習用データに合わせすぎて、新しいデータに弱くなっています。データを増やす、データのばらつきを広げる、モデルを単純にする、などの対策があります。
:::

**問3**　明るい部屋で撮った写真だけで学習したモデルを、暗い部屋で使ったら、うまく見分けられませんでした。どうすればよいですか。

:::details 答え
暗い部屋の写真や、いろいろな明るさの写真も学習用データに加えて、学習し直します。モデルは、データに入っている条件しか学べません。
:::
