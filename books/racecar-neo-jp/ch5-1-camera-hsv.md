カメラの画像は、コンピュータの中ではただの数の表です。この回では、その表から色を読みとり、「青いところだけ」のように、決まった色の部分を取り出す方法を学びます。次の 5-2（Lab E）で信号の色を見分けるための準備です。

## ① この回でできるようになること

1. カメラ画像が、画素（ピクセル）の色の数を並べた表であることを説明できる
2. 行と列を指定して、1つの画素の色を取り出せる
3. 色を BGR と HSV の2つの表し方で表し、HSV のほうが色で見分けやすい理由を説明できる
4. HSV の範囲を決めて、その色の部分だけを取り出せる（マスク）

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Pixel | 画素（ピクセル） | 画像をつくる、小さな四角の1つ1つ |
| BGR | BGR | 青（Blue）・緑（Green）・赤（Red）の強さで色を表す方法 |
| Hue | 色相（しきそう） | 赤・黄・緑・青…という「色合い」 |
| Saturation | 彩度（さいど） | あざやかさ。小さいほど白や灰色に近い |
| Value | 明度（めいど） | 明るさ。小さいほど黒に近い |
| HSV | HSV | 色を、色相・彩度・明度の3つで表す方法 |
| Mask | マスク | 条件に合う画素を白、合わない画素を黒にした画像 |
| OpenCV | OpenCV | 画像を扱うための Python のライブラリ。`cv` という名前で読みこむ |

## ③ 本文

### カメラ画像は、数の表

`rc.camera.get_color_image()` で、カメラの今の画像を受けとれます。受けとった画像は、縦 480 行・横 640 列の表で、表の1マスが1つの**画素**です。

![左はカメラ画像全体で、左上が (0, 0)。下に向かって行の番号が 0 から 479 まで増え、右に向かって列の番号が 0 から 639 まで増える。右は青い箱の一部を拡大したもので、小さな四角（画素）が並んでいる。image[170][181] の値は [205, 120, 40] で、青・緑・赤の順にそれぞれ 0 から 255 の数](/images/racecar-neo-jp/5-1/fig1-pixels.png)
*図1　カメラ画像は、画素の色を並べた表*

- 位置は **(行, 列)** の順に書きます。左上が (0, 0) で、下に行くほど行の番号が、右に行くほど列の番号が大きくなります
- 1つの画素には、**青・緑・赤**の3つの数が入っています。それぞれ 0〜255 で、大きいほどその色が強く光っています。赤・緑・青ではなく、青・緑・赤の順（**BGR**）なので気をつけましょう
- `image.shape` は `(480, 640, 3)` です。「行の数・列の数・色の数」を表しています

```python
image = rc.camera.get_color_image()
b, g, r = image[170][181]    # 170行め・181列めの画素の、青・緑・赤
```

カメラから画像が届いていないときは、`image` が `None`（何もない）になります。Lab E のひな形のように、`if image is None:` で確かめてから使うと安全です。

### BGR では、色を見分けにくい

「青い箱」を見つけたいとします。BGR で「青が強く、緑と赤が弱い」画素を選べばよさそうです。ところが、同じ青い箱でも、光の当たり方で数が大きく変わります。

| 場所 | B（青） | G（緑） | R（赤） |
|---|---|---|---|
| 光が当たった面 | 205 | 120 | 40 |
| 影になった面 | 100 | 58 | 19 |

影になると、3つの数がまとめて小さくなります。「B が 150 より大きい」のような条件では、影の面を見のがしてしまいます（図3のまん中）。

### HSV：色合い・あざやかさ・明るさ

そこで、色を別の3つの数で表します。これが **HSV** です。

- **H（色相）**：色合い。赤→黄→緑→水色→青→紫→赤と、ぐるりと一周する角度で表す
- **S（彩度）**：あざやかさ。0 だと白・灰色・黒のように色がない
- **V（明度）**：明るさ。0 だと真っ黒

![上は、OpenCV の H（色合い）の目もり。0 が赤、15 あたりがだいだい、30 が黄、60 が緑、90 が水色、120 が青、150 が紫で、179 でまた赤に戻る。下は H が 110 のときの S と V の四角。S が小さいほど白や灰色に、V が小さいほど黒に近づく](/images/racecar-neo-jp/5-1/fig2-hsv.png)
*図2　OpenCV の HSV*

さきほどの青い箱を HSV で表すと、次のようになります。

| 場所 | H（色相） | S（彩度） | V（明度） |
|---|---|---|---|
| 光が当たった面 | 105 | 205 | 205 |
| 影になった面 | 106 | 207 | 100 |

影になって大きく変わったのは V だけで、**H はほとんど変わりません**。色合いと明るさが別々の数に分かれているので、「H が青の範囲にあれば青」と、明るさに左右されずに判断できます。

:::message
**OpenCV の H は 0〜179**
H は本来 0°〜360° の角度ですが、画像の1つの数は 0〜255 までしか入れられません。そこで OpenCV では、角度を**半分**にして 0〜179 で表します。ほかの道具（お絵かきソフトなど）で調べた色合いの角度は、2で割ってから使いましょう。S と V は 0〜255 です。
:::

赤は、H の目もりの**両はし**（0 の近くと 179 の近く）にまたがっています。赤を選ぶときは、この点に注意が必要です（⑤）。

### 色の範囲で、マスクを作る

HSV の下限と上限を決めて、その範囲に入る画素を白、入らない画素を黒にした画像を**マスク**といいます。OpenCV では、次のように作ります。

```python
import cv2 as cv

hsv = cv.cvtColor(image, cv.COLOR_BGR2HSV)                 # BGR を HSV に変換
mask = cv.inRange(hsv, (90, 50, 50), (120, 255, 255))      # 青の範囲に入る画素だけ白
```

`(90, 50, 50)` から `(120, 255, 255)` は、Lab E のひな形に書かれている青の範囲です。H が 90〜120 の色合いで、しかも S と V が 50 以上の画素を選びます。S と V に下限をつけるのは、色の薄い灰色や、真っ暗な影を選ばないためです。

![左は元の画像で、青い箱とだいだい色の箱が置かれている。まん中は BGR で「B が150より大きく、G が150より小さく、R が100より小さい」画素を白にしたマスクで、青い箱の光が当たった正面だけが白くなり、影の側面と明るい上面は選ばれていない。右は HSV で (90, 50, 50) から (120, 255, 255) の範囲を白にしたマスクで、青い箱の正面・上面・影の側面がすべて白くなっている](/images/racecar-neo-jp/5-1/fig3-mask.png)
*図3　BGR で選んだ場合と、HSV で選んだ場合（説明用に作った画像）*

5-2 で使う `rc_utils.find_contours()` は、この「HSV に変換して、範囲でマスクを作る」ところを中でやってくれます。

### やってみよう：色を測る

色の範囲を決めるには、まず、見分けたい物の色が HSV でいくつなのかを測ります。次のプログラムは、A ボタンを押すと、画面の真ん中の画素の色を BGR と HSV で表示します。トリガーとスティックで車を動かせるので、測りたい物を画面の真ん中に入れてから A を押しましょう。

```python:hsv_probe.py
"""
hsv_probe.py
画面の真ん中の色を、BGR と HSV で表示する。
A ボタン（キーボードの 1）を押すたびに表示。トリガーとスティックで車を動かせる。
"""

import sys
import cv2 as cv

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()


def start():
    rc.drive.stop()
    print(">> A ボタン（キーボードの 1）で、画面の真ん中の色を表示します")


def update():
    # 手動で動かす（3-2 と同じ）
    speed = (rc.controller.get_trigger(rc.controller.Trigger.RIGHT)
             - rc.controller.get_trigger(rc.controller.Trigger.LEFT)) * 0.5
    (x, y) = rc.controller.get_joystick(rc.controller.Joystick.LEFT)
    rc.drive.set_speed_angle(speed, x)

    image = rc.camera.get_color_image()
    if image is None:
        return

    row = image.shape[0] // 2      # 真ん中の行
    col = image.shape[1] // 2      # 真ん中の列

    if rc.controller.was_pressed(rc.controller.Button.A):
        hsv = cv.cvtColor(image, cv.COLOR_BGR2HSV)   # 画像全体を HSV に変換
        b, g, r = image[row][col]
        h, s, v = hsv[row][col]
        print(f"BGR = ({b}, {g}, {r})   HSV = ({h}, {s}, {v})")

    # どこを測っているかわかるように、真ん中に白い点を描いて表示する
    rc_utils.draw_circle(image, (row, col), rc_utils.ColorBGR.white.value)
    rc.display.show_color_image(image)


if __name__ == "__main__":
    rc.set_start_update(start, update)
    rc.go()
```

`lab_e` フォルダに保存して、次のように実行します。

```bash

cd lab_e
racecar sim hsv_probe.py
```

シミュレータのレベルは、**Neo Labs** の **Lab E: Stoplight Challenge**（探索モード）がおすすめです。信号の役をする箱をクリックして選び、右クリックすると、箱の色を変えられます。画面にはカメラの画像が別のウィンドウで表示され、真ん中に白い点が付きます。A を押すと、次のような形で表示されます（数は、見ている物や光の当たり方で変わります）。

```text
BGR = (101, 60, 14)   HSV = (104, 220, 101)
```

#### 範囲の決め方

1つの点を1回測っただけでは、範囲は決められません。次のように測って、範囲を広げていきます。

1. 同じ物の、光が当たったところと影になったところを測る
2. 近くからと遠くから測る
3. 測った H の最小と最大に、少し余裕（5〜10 くらい）を足して、H の範囲にする
4. S と V の下限は、灰色の床や壁、暗い影を選ばない値にする。ひな形の青の範囲では 50 になっている
5. 決めた範囲でマスクを作り、ほかの色の物が選ばれていないか確かめる（④）

## ④ 数式・コード

### マスクを画面に表示して確かめる

決めた範囲が正しいかは、マスクそのものを見るのがいちばん確かです。`hsv_probe.py` の最後の2行を、次のように置きかえます。

```python
hsv = cv.cvtColor(image, cv.COLOR_BGR2HSV)
mask = cv.inRange(hsv, (90, 50, 50), (120, 255, 255))
rc.display.show_color_image(cv.cvtColor(mask, cv.COLOR_GRAY2BGR))
```

マスクは白と黒の1色だけの画像なので、`cv.COLOR_GRAY2BGR` で3色の形に直してから表示しています。見分けたい物だけが白くなり、ほかは黒くなっていれば成功です。

### BGR から HSV への計算

OpenCV の変換は、次の計算をしています。$B, G, R$ はそれぞれ 0〜255 です。

$$
V = \max(B, G, R), \qquad
S = \frac{V - \min(B, G, R)}{V} \times 255
$$

H は、いちばん強い色がどれかで式が変わります（$m = \min(B, G, R)$）。

$$
H_{[°]} =
\begin{cases}
60 \times \dfrac{G - B}{V - m} & (V = R \text{ のとき}) \\[2ex]
120 + 60 \times \dfrac{B - R}{V - m} & (V = G \text{ のとき}) \\[2ex]
240 + 60 \times \dfrac{R - G}{V - m} & (V = B \text{ のとき})
\end{cases}
$$

$H_{[°]}$ がマイナスになったら 360 を足し、最後に2で割ったものが、OpenCV の H です。Python で書くと、次のようになります。

```python:bgr_to_hsv.py
def bgr_to_hsv(b, g, r):
    """BGR（各 0〜255）を、OpenCV と同じ HSV（H は 0〜179、S と V は 0〜255）に直す"""
    v = max(b, g, r)                  # いちばん強い色の値
    m = min(b, g, r)                  # いちばん弱い色の値
    if v == m:                        # 3つとも同じ → 白・灰・黒（色合いがない）
        return 0, 0, v
    s = (v - m) / v * 255
    if v == r:
        h = 60 * (g - b) / (v - m)          # 赤に近い（-60°〜60°）
    elif v == g:
        h = 120 + 60 * (b - r) / (v - m)    # 緑に近い（60°〜180°）
    else:
        h = 240 + 60 * (r - g) / (v - m)    # 青に近い（180°〜300°）
    if h < 0:
        h += 360                      # 角度をプラスにそろえる
    return round(h / 2) % 180, round(s), v   # H は角度を半分にして 0〜179 に収める


print(bgr_to_hsv(0, 0, 255))      # 赤
print(bgr_to_hsv(0, 255, 255))    # 黄
print(bgr_to_hsv(0, 255, 0))      # 緑
print(bgr_to_hsv(255, 0, 0))      # 青
print(bgr_to_hsv(205, 120, 40))   # 図1の青い箱の色
print(bgr_to_hsv(100, 58, 19))    # 影になった青
```

```text
(0, 255, 255)
(30, 255, 255)
(60, 255, 255)
(120, 255, 255)
(105, 205, 205)
(106, 207, 100)
```

2万通りの色で OpenCV の結果と比べると、ちがいは端数の丸め方による 1 以内でした。

## ⑤ つまずきポイント

### 赤が見つからない（H の範囲が 0 と 179 をまたぐ）

赤の H は、0 の近くと 179 の近くの両方にあります。`cv.inRange` にそのまま「170〜10」のような範囲を渡しても、下限が上限より大きいので、何も選ばれません。

`cv.inRange` を使うときは、「170〜179」と「0〜10」の2つのマスクを作って合わせます。5-2 で使う `rc_utils.find_contours()` は、下限の H が上限の H より大きいとき、自動でこの2つを合わせてくれます。そのため、赤は `((170, 50, 50), (10, 255, 255))` のように書けます。

### 赤っぽい画素の H を平均したら、水色になった

H は、ぐるりと一周する角度です。H が 2 と 178 の画素はどちらも赤ですが、ふつうに平均すると $(2 + 178) \div 2 = 90$ で、水色になってしまいます。H を平均しないか、赤は上のように2つの範囲で扱いましょう。

### 測った色が、真っ白 (255, 255, 255) になる

白い点を描いてから測ると、その点の色を測ってしまいます。`hsv_probe.py` のように、**測ってから**点を描きます。

### `image[x][y]` と書いてしまう

画像の位置は (行, 列) の順で、行は上から下、列は左から右です。数学の (x, y) とは順番が逆なので注意しましょう。なお、OpenCV の図形を描く関数（`cv.circle` など）は (x, y) ＝ (列, 行) の順で受けとります。`rc_utils.draw_circle()` は (行, 列) で受けとり、中で並べ替えてくれます。

### シミュレータで決めた範囲が、実機では合わない

実機のカメラ画像は、部屋の明かりや、カメラが自動で行う色の調整によって、シミュレータとは色が変わります。実機では、実機のカメラで測り直しましょう。

## ⑥ 確認問題

**問1**　`image.shape` が `(480, 640, 3)` のとき、いちばん右下の画素の色はどう書けば取り出せますか。また、`image[480][0]` と書くとどうなりますか。

:::details 答え
`image[479][639]` です。行も列も 0 から数えるので、いちばん最後は「数 − 1」になります。
`image[480][0]` は、ない行を指定しているので `IndexError` で止まります。
:::

**問2**　BGR が `(0, 255, 255)` の色は何色で、OpenCV の H はいくつですか。④の式を使って求めましょう。

:::details 答え
緑と赤が同じだけ光っているので、黄色です。いちばん強い値 $V$ は 255 で、G と R の両方が 255 ですが、コードでは `v == r` が先に調べられるので、1つめの式を使います。$60 \times (255 - 0) / (255 - 0) = 60$ です。
$H_{[°]} = 60$ を2で割って、OpenCV の H は **30** です。
:::

**問3**　赤い箱を `rc_utils.find_contours()` で見つけたいとき、HSV の範囲はどのように書けばよいですか。

:::details 答えの例
H が 170〜179 と 0〜10 の両方を選びたいので、下限の H を上限の H より大きくして、`((170, 50, 50), (10, 255, 255))` のように書きます。`find_contours()` は、この場合に2つのマスクを作って合わせてくれます。H の数値は、実際に測って決めましょう。
:::

**問4**　同じ青い箱の、光が当たった面と影になった面で、HSV の3つの数のうち大きく変わるのはどれですか。

:::details 答え
V（明度）です。影になると明るさが下がるので V は大きく下がりますが、H（色合い）はほとんど変わりません。
:::
