6-10 までで、揺れずに目標の距離へ落ち着く壁沿い走行ができました。ところが、曲がった壁にそって走ると、目標から少しずれた所で落ち着いてしまい、そのずれがいつまでも消えないことがあります。この回では、ずれを**時間をかけてためていく** I（積分）を加えて、残ったずれを消します。これで P・I・D の3つがそろいます。

## ① この回でできるようになること

1. P 制御だけでは、ずれが残ってしまう場面を説明できる
2. ずれの積分を、毎コマの足し算で求められる
3. I を加えて、残ったずれを消せる
4. KI を大きくしすぎると、行き過ぎや揺れが出ることを説明できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Steady-state error | 定常偏差（残るずれ） | 落ち着いたあとも、ずっと残るずれ |
| Integral (I) | 積分（I） | ずれ × 時間を、ずっと足し合わせたもの |
| Integral gain | 積分ゲイン（KI） | ずれの積分を何倍して命令にするか |
| PID control | PID 制御 | P・I・D の3つを足して命令を決める方法 |

## ③ 本文

### ずれが残るのは、どんなときか

P の部分は、ずれに比例した命令を出します。ずれが 0 なら、命令も 0 です。ところが、**目標の所にいるのに、0 ではない命令を出し続けなければならない**場面があります。

- **曲がった壁**：丸い部屋の壁にそって走るには、ハンドルを切り続ける必要がある
- **ハンドルのくせ**：実物の車には、angle を 0 にしても少し右（または左）に曲がってしまうものがある。まっすぐ走るには、少し反対に切り続ける必要がある
- **摩擦**：6-1 で見たように、実物の車は、speed が小さすぎると動かない。目標の手前で止まったまま、動き出せない

こういうとき、P だけの制御では、必要な命令を出すために、**わざとずれを残した所**で落ち着いてしまいます。このずれを**定常偏差**といいます。

### 丸い部屋で確かめる

説明用の簡単なモデルで、半径 250 cm の丸い部屋の中を、右の壁から 50 cm の所を保って走らせました。制御は 6-10 と同じ「距離のずれ ＋ 壁の向き」（KP 0.02、KA 0.04）です。

すると、車は壁から **34.7 cm** の所で落ち着き、そのまま回り続けました。目標より 15 cm も壁に近い所です。この部屋を回るには、ハンドルを左にいくらか切り続ける必要があります。P の部分がそのハンドルを出すには、ずれが－（壁に近すぎる）でなければなりません。だから、壁に近い所で落ち着いてしまうのです。

### I：ずれを、時間をかけてためていく

そこで、ずれを毎コマ足し合わせていく変数 `integral` を用意します。

```python
integral += error * rc.get_delta_time()     # ずれ × 1コマの時間 を足していく
angle = KP * error + KI * integral + KA * wall_angle
```

ずれが－のまま続くと、`integral` は、どんどん－の方向に大きくなっていきます。そのぶん、I の部分（`KI * integral`）も大きくなり、ハンドルを左に切る量がふえていきます。車は壁から離れていき、ずれは小さくなります。

大事なのは、**ずれが 0 になっても、それまでにためた `integral` は残る**ことです。つまり、I の部分は、ずれがなくても、必要なハンドルを出し続けられます。I の部分が、曲がり続けるのに必要なハンドルを受け持つようになると、P の部分は 0 でよくなり、ずれが消えます。

### やってみよう：I を加えて走る

6-10 の `wall_follow_angle.py` に、I を加えたプログラムです。

```python:wall_follow_i.py
"""
wall_follow_i.py
右の壁から TARGET cm の距離を保って走る。
6-10 の「距離のずれ ＋ 壁の向き」に、ずれをためていく I（積分）を足したもの。
"""

import sys
import math

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

TARGET = 50.0     # 右の壁から保ちたい距離（cm）
SPEED = 0.5       # 走る速さ（一定）
KP = 0.02         # 距離のずれに対するゲイン
KI = 0.005        # ずれの積分に対するゲイン（I）
KA = 0.04         # 壁の向き（1°あたり）に対するゲイン
THETA = 30        # 2本の光線の間の角度（度）

distance = None   # 右の壁までの距離（update_slow で表示する）
wall_angle = 0.0  # 壁の向き（度）。＋：壁から離れる向きに走っている
angle = 0.0
integral = 0.0    # ずれの積分（cm・秒）


def right_wall(scan):
    """右の壁の向き（度）と、壁までの距離（cm）を返す。測れなければ (None, None)"""
    a = rc_utils.get_lidar_average_distance(scan, 90 - THETA)   # ななめ前（60°）の距離
    b = rc_utils.get_lidar_average_distance(scan, 90)           # 真横（90°）の距離
    if a == 0.0 or b == 0.0:
        return None, None
    t = math.radians(THETA)
    alpha = math.atan2(a * math.cos(t) - b, a * math.sin(t))   # 壁の向き（ラジアン）
    return math.degrees(alpha), b * math.cos(alpha)


def start():
    global integral
    rc.drive.stop()
    integral = 0.0
    print(f">> 右の壁から {TARGET:.0f} cm を保って走ります（距離のずれ ＋ ずれの積分 ＋ 壁の向き）")


def update():
    global distance, wall_angle, angle, integral

    scan = rc.lidar.get_samples()
    wall_angle, distance = right_wall(scan)

    if distance is None:
        angle = 0.0
    else:
        error = distance - TARGET
        integral += error * rc.get_delta_time()          # ずれを、時間をかけてためていく
        angle = rc_utils.clamp(KP * error + KI * integral + KA * wall_angle, -1.0, 1.0)

    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    if distance is None:
        print("壁が見えない")
    else:
        print(f"右の壁まで {distance:5.1f} cm　ずれ {distance - TARGET:+5.1f} cm　I の部分 {KI * integral:+.3f}　angle {angle:+.2f}")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

### KI の大きさ

KI をかえて、丸い部屋を 20 秒走らせました（どれも KP 0.02、KA 0.04）。

| KI | 0 | 0.002 | 0.005 | 0.01 | 0.02 |
|---|---|---|---|---|---|
| 最後の 2 秒の距離 | 34.7 cm | 47.9 cm | 50.1 cm | 50.1 cm | 50.4 cm |
| いちばん近づいた距離 | 33.8 cm | 35.7 cm | 37.1 cm | 38.4 cm | 39.8 cm |
| いちばん離れた距離 | 50.0 cm | 50.0 cm | 50.6 cm | 52.8 cm | 56.6 cm |

- **KI が小さすぎる**（0.002）：ずれは少しずつ消えていくが、20 秒たってもまだ 2 cm 残っている
- **KI がちょうどよい**（0.005）：10 秒ほどで、ずれが消える
- **KI が大きすぎる**（0.02）：早く目標にもどろうとするが、ためすぎて反対に行き過ぎ（56.6 cm）、揺れながら落ち着く

I は、ずれを「ためて」から効くので、どうしても**少し遅れて**はたらきます。遅れてはたらく力を強くしすぎると、6-8 で見たように、行き過ぎや揺れの原因になります。KI は、P や D よりも小さめから試しましょう。

### ハンドルのくせも消せる

まっすぐな壁でも、同じことが起きます。モデルで、「angle を 0 にしても、angle = 0.1 のぶん右に曲がってしまう車」にして、6-10 の方法で走らせると、車は壁から 44.8 cm の所で落ち着きました。KI = 0.005 の I を加えると、50.0 cm になりました。

実物の車では、ハンドルの取りつけのずれや、タイヤの空気の入り方の違いで、こうしたくせがよくあります。I は、こうした「何が原因かわからないけれど、いつも同じ向きにずれる」ものを、まとめて消してくれます。

### 6-1 の続き：摩擦で止まってしまうずれ

6-1 の「壁の手前 50 cm で止まる」でも、実物の車では、speed が小さすぎると動かないので、ずれが残ります。これも I で消せます。

```python:stop_at_wall_pi.py
"""
stop_at_wall_pi.py
正面の壁の手前 TARGET cm で止まる（P ＋ I）。
6-1 の stop_at_wall.py に、ずれをためていく I を足したもの。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

TARGET = 50.0     # 止まりたい、壁までの距離（cm）
KP = 0.02         # P のゲイン
KI = 0.01         # I のゲイン

front = 0.0       # 正面の壁までの距離（update_slow で表示する）
integral = 0.0    # ずれの積分（cm・秒）


def start():
    global integral
    rc.drive.stop()
    integral = 0.0
    print(f">> 正面の壁の手前 {TARGET:.0f} cm で止まります（P ＋ I）")


def update():
    global front, integral
    scan = rc.lidar.get_samples()
    _, front = rc_utils.get_lidar_closest_point(scan, (350, 10))
    error = front - TARGET
    integral += error * rc.get_delta_time()                    # ずれをためていく
    speed = rc_utils.clamp(KP * error + KI * integral, -1.0, 1.0)
    rc.drive.set_speed_angle(speed, 0.0)


def update_slow():
    print(f"正面の壁まで {front:6.1f} cm　I の部分 {KI * integral:+.3f}")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

説明用の簡単なモデルに、「|speed| が 0.15 より小さいと、車は動かない」という摩擦を入れて、壁から 100 cm の所から走らせました。

- **P だけ**（6-1 のまま）：壁から 46.2 cm で止まり、そのまま動かない（ずれ 3.8 cm）
- **P ＋ I**（KI 0.01）：いったん 33.6 cm まで近づいてから、少しずつもどり、約 9 秒で 50.9 cm の所に止まった

P ＋ I の表示は、次のとおりです。行き過ぎて壁に近すぎる所で止まったあと、I の部分が－の向きに少しずつ大きくなっていきます。speed の大きさが 0.15 をこえると、車は後ろへ動き出し、目標に近づいていきます。

## ④ 数式・コード

### 積分は「ずれのグラフの面積」

ずれ $e$ を、たてに時間 $t$ を横にとったグラフを考えます。積分は、このグラフと横軸の間の**面積**です。

$$
\text{integral} = \int_0^{t} e \, dt \approx \sum e_k \, \Delta t
$$

プログラムでは、毎コマ「ずれ × 1コマの時間」（細長い長方形の面積）を足していくことで、この面積を求めています。ずれが＋の間は面積がふえ、－の間は減ります。

### KI の単位

`integral` の単位は「cm × 秒」です。angle には単位がないので、KI の単位は「1/(cm・秒)」です。`KI = 0.005` なら、「10 cm のずれが 2 秒続くと、I の部分が $0.005 \times 10 \times 2 = 0.1$ ふえる」という意味です。

### ハンドルのくせで残るずれの大きさ

ハンドルのくせを $b$（angle でいくつぶん曲がってしまうか）とします。まっすぐな壁と平行に走って落ち着いたとき、壁の向きは 0 なので、P だけなら、

$$
K_P \times e + b = 0 \quad\Rightarrow\quad e = -\frac{b}{K_P}
$$

$b = 0.1$、$K_P = 0.02$ なら、$e = -5$ cm です。モデルの 44.8 cm（ずれ −5.2 cm）とほぼ同じです。KP を大きくすると、残るずれは小さくなりますが、0 にはなりません。I なら 0 にできます。

## ⑤ つまずきポイント

### `integral` を start() で 0 にもどしていない

`start()` で `integral = 0.0` にしないと、前に走ったときにためた値が残ったまま走り出します。走り出したとたんに、大きくハンドルを切ってしまいます。

### KI の符号をまちがえる

I の部分は、P の部分と同じ向きにはたらくようにします。P で `KP * error` と書いたなら、I も `KI * integral`（＋）です。左の壁にそって走るとき（6-7）のように、P の前に－をつけたなら、I の前にも－をつけます。

### 遠くから走り出すと、大きく行き過ぎる

走り出しのずれが大きいと、I がたまりすぎて、大きく行き過ぎます。6-12 で、ためすぎを防ぐ方法を学びます。

## ⑥ 確認問題

**問1**　1コマを 1/60 秒とします。ずれが −6 cm のまま 3 秒続きました。`integral` は、はじめの 0 からいくつになりますか。

:::details 答え
$-6 \times 3 = -18$（cm・秒）です。1コマごとに $-6 \times \frac{1}{60} = -0.1$ ずつ、180 コマ足されます。
:::

**問2**　問1 のとき、`KI = 0.005` なら、I の部分はいくつですか。

:::details 答え
$0.005 \times (-18) = -0.09$ です。
:::

**問3**　丸い部屋で、P だけ（I なし）の車が、壁に近い所で落ち着いてしまうのはなぜですか。

:::details 答え
部屋を回るには、ハンドルを切り続ける必要があります。P の部分がそのハンドルを出すには、ずれが 0 ではいけないので、ずれが残った所で落ち着くからです。
:::
