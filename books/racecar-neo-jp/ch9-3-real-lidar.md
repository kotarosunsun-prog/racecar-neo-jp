実機の LIDAR も、シミュレータと同じ 720 点の距離を返します。並び方も単位も同じなので、第7章・第8章のプログラムは、そのまま実機で動かせます。ちがうのは、測る相手です。シミュレータの壁は、どれもきれいに測れました。実機の LIDAR は、ガラスや鏡、黒い物を、うまく測れないことがあります。この回では、そのような物が LIDAR でどう見えるかと、その対策を学びます。

## ① この回でできるようになること

1. `rc.lidar` の関数と、返ってくる値の形（点の数・並び方・単位）を言える
2. ガラス・鏡・黒い物が LIDAR でどう見えるかを説明できる
3. コースを走る前に、LIDAR の値を確かめ、対策できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Sample | 点（サンプル） | LIDAR が 1 回転で測る、1 つ 1 つの距離 |
| Angular resolution | 角度の分解能 | となりの点との角度の差 |
| Index | 番号 | 配列の何番めか。`scan[180]` の 180 |

## ③ 本文

### 実機の LIDAR の値

`rc.lidar` には、次の関数があります（関数の定義集より）。

| 関数 | 返すもの |
|---|---|
| `rc.lidar.get_samples()` | 1 回転ぶんの距離の配列（cm）。0 番が車の真正面で、時計回りに並ぶ。となりの点との角度は、どこも同じ |
| `rc.lidar.get_num_samples()` | 1 回転の点の数 |
| `rc.lidar.get_samples_async()` | `get_samples()` と同じ値を、`go()` で動かしていないときに読む。Jupyter Notebook 用で、`start()`・`update()` のプログラムでは使わない |

シミュレータと実機をくらべると、次のようになります。

| | シミュレータ | 実機 |
|---|---|---|
| 1 回転の点の数 | 720 | 720 |
| となりの点との角度 | 0.5° | 0.5° |
| 並び方・単位・測れない点 | 正面が 0 番、時計回り、cm、測れない所は 0.0 | 同じ |
| 1 秒に回る回数 | 約 6 回（この本のモデル） | 約 10 回 |
| 測りにくい物 | ほとんどない | ガラス・鏡・黒い物 |

`rc.lidar.get_num_samples()` を使うと、点の数を数字で書かずにすみます。関数の定義集には、真後ろの距離を読む例がのっています。

```python
scan = rc.lidar.get_samples()
rear_distance = scan[rc.lidar.get_num_samples() // 2]   # 720 // 2 = 360 番：真後ろ
```

この本の第7章・第8章のプログラムも、`lidar_angles()` のように、点の数を `len(scan)` から求めています。720 と書いてもまちがいではありませんが、配列の長さから求めておくと、何の数なのかが読みやすくなります。

```python
def lidar_angles(scan):
    """LIDAR の各点の角度（ラジアン）。0 が正面、時計回り。
    点の数は len(scan) から求める（720 点なら 0.5° ずつ）"""
    return np.radians(np.arange(len(scan)) * 360 / len(scan))
```

### ガラス・鏡・黒い物

実機の LIDAR は、レーザーの光を当てて、はね返ってくるまでの時間で距離を測ります。そのため、光がうまくはね返らない物は、測れないことがあります。

- **ガラス**（透明な物）：光が通りぬけて、向こうの物までの距離になる。向こうに何もなければ 0.0
- **鏡**（よく光る金属も）：光がほかの向きへはね返り、鏡に映った物までの距離になる。鏡の奥に、もう1つ部屋があるように見える
- **黒い物**（光を吸う物）：はね返る光が弱く、0.0 になったり、値がばらついたりする

この本のプログラムは、0.0 を「何もない」として扱っています。7-1 の `safety_stop.py` は 0.0 の点を使わず、`gaps.py` は 0.0 を遠く（`MAX_RANGE`）とみなします。どちらも、ガラスがあっても、そこは空いていると判断します。

### コースを走る前に確かめる

次のプログラムは、LIDAR を 8 つの向きに分けて、測れなかった点の割合と、いちばん近い物までの距離を表示します。車をコースのあちこちに置いて、表示を見くらべます。

```python:lidar_check.py
"""
lidar_check.py
LIDAR を 8 つの向き（45° ずつ）に分けて、測れなかった点（0.0）の割合と、いちばん近い物までの距離を表示する（9-3）。
ガラス・鏡・黒い物・遠すぎる所は、0.0 になりやすい。コースを走る前に、車を置いて確かめる。車は動かさない。
"""

import sys

import numpy as np

sys.path.insert(1, "../../library")
import racecar_core

rc = racecar_core.create_racecar()

NAMES = ["前", "右前", "右", "右後ろ", "後ろ", "左後ろ", "左", "左前"]


def start():
    rc.drive.stop()
    print(">> 向きごとに、測れなかった点の割合と、いちばん近い物までの距離を表示します")


def update():
    rc.drive.stop()


def update_slow():
    scan = rc.lidar.get_samples()
    n = len(scan)                                    # 点の数（720）
    angles = np.arange(n) * 360 / n                  # 各点の角度（度）。0 が正面、時計回り
    sector = ((angles + 22.5) // 45).astype(int) % 8  # 前（-22.5°〜22.5°）が 0、そこから時計回りに 1、2、…
    words = []
    for k in range(8):
        part = scan[sector == k]
        zero = 100 * np.mean(part == 0)              # 0.0 の点の割合（%）
        near = part[part > 0].min() if (part > 0).any() else 0.0
        words.append(f"{NAMES[k]} {zero:3.0f}% {near:4.0f}cm")
    print(" | ".join(words))


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

図1の廊下で、板の 150 cm 手前に車を置いたとき、モデルでは次のように表示されました（実機の値ではありません）。

```text
（見える板のとき）
前   0%  146cm | 右前   0%   82cm | 右   0%   72cm | 右後ろ   0%   77cm | 後ろ   0%  192cm | 左後ろ   0%   80cm | 左   0%   72cm | 左前   0%   81cm
（ガラスの板のとき）
前   0%  200cm | 右前   0%   82cm | 右   0%   72cm | 右後ろ   0%   77cm | 後ろ   0%  192cm | 左後ろ   0%   80cm | 左   0%   72cm | 左前   0%   81cm
```

ガラスのときは、「前」の測れない点の割合は 0% のままで、いちばん近い物は 200 cm（廊下の横の壁）になりました。ガラスまでの 150 cm は、どこにも出てきません。**ガラスは、LIDAR の値だけでは見つけられない**ことがあるのです。巻き尺で測った距離と、表示された距離をくらべて、ちがう所がないか確かめましょう。

コースの準備として、次のことをしましょう。

1. ガラスの戸や窓、鏡、光る金属の板の、LIDAR の高さのところに、紙や養生テープを貼るか、段ボールでおおう
2. 黒い物（黒いカバンや、黒い布）は、コースのそばに置かない
3. `lidar_check.py` で、測れない点が多い向きや、巻き尺とちがう距離がないか確かめる
4. 走らせるときは、いつでも RB をはなせるように、車を見ている（9-1）

## ④ 数式・コード

### 角度から番号を求める

点の数を $n$ とすると、角度 $\theta$（度）の点の番号 $i$ は、次のとおりです（5-3）。

$$
i = \operatorname{round}\left(\theta \times \frac{n}{360}\right)
$$

$n = 720$ なら、90°（右）は 180 番、270°（左）は 540 番です。`racecar_utils` の `get_lidar_average_distance()` なども、この計算をしています。

### 鏡に映った物までの距離

鏡まで $a$ cm、鏡から映っている物まで $b$ cm のとき、LIDAR が測る距離は $a + b$ cm です。光は、鏡ではね返ってから、映っている物まで行って、同じ道をもどってくるからです。LIDAR は、光がまっすぐ進んだと考えるので、鏡の向こう $b$ cm のところに物があるように見えます。

## ⑤ つまずきポイント

### 巻き尺で測った距離と、LIDAR の距離が合わない

LIDAR は、車の中心ではなく、LIDAR そのものからの距離を測ります。巻き尺も、LIDAR の真ん中から測りましょう。それでも大きくずれる向きがあれば、ガラスや鏡、黒い物がないか確かめます。

### 窓の近くで、車が急に曲がる・止まらない

窓ガラスや、ガラスの戸が、「空いている」と見えている可能性があります。`lidar_check.py` と巻き尺で確かめ、テープや段ボールでおおいましょう。

## ⑥ 確認問題

**問1**　LIDAR（720 点）で、左（270°）の距離の番号は何番ですか。

:::details 答え
$270 \times 720 / 360 = 540$ 番です。
:::

**問2**　`scan[90]` は、何度の向きの距離ですか。

:::details 答え
$90 \times 360 / 720 = 45$ 度（右ななめ前）です。
:::

**問3**　正面 100 cm のところに鏡があり、鏡に映っている壁は、鏡から 150 cm のところにあります。LIDAR の正面の距離は、何 cm になりますか。

:::details 答え
$100 + 150 = 250$ cm です。鏡があるのに、250 cm 先まで何もないように見えます。
:::
