シミュレータの LIDAR は 720 点でしたが、実機の LIDAR は約 1080 点を返します。点の番号で向きを決めているプログラムは、実機ではちがう向きを見てしまいます。また、実機の LIDAR は、ガラスや鏡、黒い物を、うまく測れないことがあります。この回では、この2つのちがいと、その対策を学びます。

## ① この回でできるようになること

1. シミュレータと実機の LIDAR の点の数と、1 点あたりの角度を言える
2. 点の番号ではなく、角度で書くことで、どちらでも動くプログラムにできる
3. ガラス・鏡・黒い物が LIDAR でどう見えるかを説明し、コースを走る前に対策できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Sample | 点（サンプル） | LIDAR が 1 回転で測る、1 つ 1 つの距離 |
| Angular resolution | 角度の分解能 | となりの点との角度の差 |
| Index | 番号 | 配列の何番めか。`scan[180]` の 180 |
| Hard-code | 決めうち | 変わるかもしれない値を、数字で直接書くこと |
| Transparent | 透明 | 光（レーザー）が通りぬけること |
| Specular reflection | 鏡のような反射 | 光が、決まった向きにはね返ること |

## ③ 本文

### 720 点と 1080 点

| | シミュレータ | 実機 |
|---|---|---|
| 1 回転の点の数 | 720 | 約 1080 |
| となりの点との角度 | 0.5° | 約 0.33° |
| 1 秒に回る回数 | 約 6 回（この本のモデル） | 約 10 回 |
| 並び方・単位・測れない点 | 正面が 0 番、時計回り、cm、測れない所は 0.0 | 同じ（ライブラリが、シミュレータに合わせて並べ直している） |

実機のライブラリは、LIDAR の値を m から cm に直し、並ぶ向きを時計回りにそろえ、測れなかった所（無限大）を 0.0 にしています。そのため、並び方と単位は、シミュレータと同じです。ちがうのは、点の数です。

### 番号で書くと、実機では向きがずれる

シミュレータでは、`scan[180]` は右（90°）の距離でした。$180 \times 0.5 = 90$ だからです。ところが実機では、$180 \times 0.33 \approx 60$ なので、`scan[180]` は右ななめ前（60°）の距離になります。

![左：右の壁まで 50 cm のとき、720 点では scan[180] が 90° を向いて 50 cm、1080 点では 60° を向いて 57.7 cm になる。中：ガラスの板がある廊下で、1080 点の LIDAR にはガラスの点がなく、向こうの壁が見えている。右：safety_stop.py で板に向かって走ると、見える板の手前では止まるが、ガラスの板にはぶつかる](/images/racecar-neo-jp/9-3/fig1-lidar-real.png)
*図1　左：同じ番号でも、点の数で向きが変わる。中・右：説明用の簡単なモデル（1080 点・1 秒に 10 回転の LIDAR）で、ガラスの板を置いた廊下*

右の壁まで 50 cm のとき、60° の向きの距離は $50 \div \sin 60° \approx 57.7$ cm です（図1の左）。壁沿い走行なら、壁から離れていると思って、壁のほうへ寄っていきます。

番号ではなく、角度で書けば、この問題は起きません。

- `rc_utils.get_lidar_average_distance(scan, 90)` のように、角度を渡す `racecar_utils` の関数は、中で `len(scan)` から番号を計算するので、どちらでも正しい向きを見ます
- 自分で番号を計算するときは、720 や 0.5 と書かずに、`len(scan)` を使います

```python
def lidar_angles(scan):
    """LIDAR の各点の角度（ラジアン）。0 が正面、時計回り。
    点の数は len(scan) から求める（シミュレータは 720 点、実機は 1080 点。9-3）"""
    return np.radians(np.arange(len(scan)) * 360 / len(scan))
```

これは、7-1 の `safety_stop.py` などで使っている関数です。この本の第6章〜第8章のプログラムは、`racecar_utils` の関数を使うか、`len(scan)` から番号や角度を求めています。

- `safety_stop.py`（7-1）・`patrol.py`（7-2）・`combo_follow.py`（7-13）・`grand_prix.py`（8-1）：`lidar_angles()` で角度を求める
- `gaps.py`（7-6〜）の `front_view()`：`step = 360 / len(scan)` で、1 点の角度を求める（コメントの「0.5°」「-180 … 180」は、シミュレータのときの値です）
- `gap_follow.py` のはじめの版（7-7）：空きの角度の表示に、`front_view()` が返した角度を使う

ただし、6-6 の `right_wall_distance()` と 7-3 の `cone_park.py` は、いちばん近い点の「前後 10 番（±5°）」の平均をとっています。実機では、10 番は約 3.3° なので、平均する範囲が ±3.3° にせまくなります。動きはしますが、シミュレータと同じ ±5° にしたいときは、`k = round(5 * len(scan) / 360)` を求めて、番号 `center - k` から `center + k` までを使います（720 点なら k = 10、1080 点なら k = 15）。

:::message
ライブラリの説明には、点の数は `rc.lidar.get_num_samples()` で調べるように書かれています。ただ、実機の LIDAR が 1 回転で返す点の数は「約」1080 で、少し変わることがあります。この本では、実際に受けとった配列の長さ `len(scan)` を使っています。
:::

### 1080 点の LIDAR で走らせてみる

この本のモデルの LIDAR を、1080 点・1 秒に 10 回転に変えて、第7章と第8章のプログラムを 5 回ずつ走らせました。

| プログラム | シミュレータに近い LIDAR（720 点・6 回転） | 実機に近い LIDAR（1080 点・10 回転） |
|---|---|---|
| `combo_follow.py`（7-13、コース D） | 4 回ゴール（64.1〜105.2 秒）、1 回ぶつかった | 4 回ゴール（63.0〜75.2 秒）、1 回ぶつかった |
| `grand_prix.py`（8-1） | 5 回とも止まった（79.0〜81.6 秒） | 5 回とも止まった（78.9〜82.2 秒） |
| `combo_follow.py` の角度を `np.arange(720) * 0.5` と決めうちした版 | 動く | 1 コマめでエラー |

決めうちした版は、次のエラーで止まりました。1080 個の距離と 720 個の角度をかけ算しようとしたからです。

```text
ValueError: operands could not be broadcast together with shapes (1080,) (720,)
```

エラーで止まるのは、まだよいほうです。`scan[180]` のような書き方は、エラーにならずに、まちがった向きを見続けます。

### ガラス・鏡・黒い物

実機の LIDAR は、レーザーの光を当てて、はね返ってくるまでの時間で距離を測ります。そのため、光がうまくはね返らない物は、測れないことがあります。

- **ガラス**（透明な物）：光が通りぬけて、向こうの物までの距離になる。向こうに何もなければ 0.0
- **鏡**（よく光る金属も）：光がほかの向きへはね返り、鏡に映った物までの距離になる。鏡の奥に、もう1つ部屋があるように見える
- **黒い物**（光を吸う物）：はね返る光が弱く、0.0 になったり、値がばらついたりする

この本のプログラムは、0.0 を「何もない」として扱っています。7-1 の `safety_stop.py` は 0.0 の点を使わず、`gaps.py` は 0.0 を遠く（`MAX_RANGE`）とみなします。どちらも、ガラスがあっても、そこは空いていると判断します。

図1の中と右は、この本のモデルで、廊下を横切るガラスの板を置いたときです。LIDAR にはガラスの点がなく、向こうの壁が見えています。`safety_stop.py` で板に向かって走ると、見える板なら 28 cm 手前で止まりましたが、ガラスの板にはそのままぶつかりました。

### コースを走る前に確かめる

次のプログラムは、LIDAR を 8 つの向きに分けて、測れなかった点の割合と、いちばん近い物までの距離を表示します。車をコースのあちこちに置いて、表示を見くらべます。

```python:lidar_check.py
"""
lidar_check.py
LIDAR を 8 つの向き（45° ずつ）に分けて、測れなかった点（0.0）の割合と、いちばん近い物までの距離を表示する（9-3）。
ガラス・鏡・黒い物・遠すぎる所は、0.0 になりやすい。コースを走る前に、車を置いて確かめる。車は動かさない。
"""

import sys

import numpy as np

sys.path.insert(1, "../../library")
import racecar_core

rc = racecar_core.create_racecar()

NAMES = ["前", "右前", "右", "右後ろ", "後ろ", "左後ろ", "左", "左前"]


def start():
    rc.drive.stop()
    print(">> 向きごとに、測れなかった点の割合と、いちばん近い物までの距離を表示します")


def update():
    rc.drive.stop()


def update_slow():
    scan = rc.lidar.get_samples()
    n = len(scan)                                    # シミュレータは 720、実機は 1080
    angles = np.arange(n) * 360 / n                  # 各点の角度（度）。0 が正面、時計回り
    sector = ((angles + 22.5) // 45).astype(int) % 8  # 前（-22.5°〜22.5°）が 0、そこから時計回りに 1、2、…
    words = []
    for k in range(8):
        part = scan[sector == k]
        zero = 100 * np.mean(part == 0)              # 0.0 の点の割合（%）
        near = part[part > 0].min() if (part > 0).any() else 0.0
        words.append(f"{NAMES[k]} {zero:3.0f}% {near:4.0f}cm")
    print(" | ".join(words))


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

図1の廊下で、板の 150 cm 手前に車を置いたとき、モデルでは次のように表示されました（実機の値ではありません）。

```text
（見える板のとき）
前   0%  147cm | 右前   0%   81cm | 右   0%   72cm | 右後ろ   0%   81cm | 後ろ   0%  194cm | 左後ろ   0%   80cm | 左   0%   71cm | 左前   0%   78cm
（ガラスの板のとき）
前   0%  195cm | 右前   0%   81cm | 右   0%   72cm | 右後ろ   0%   81cm | 後ろ   0%  194cm | 左後ろ   0%   80cm | 左   0%   71cm | 左前   0%   78cm
```

ガラスのときは、「前」の測れない点の割合は 0% のままで、いちばん近い物は 195 cm（廊下の横の壁）になりました。ガラスまでの 150 cm は、どこにも出てきません。**ガラスは、LIDAR の値だけでは見つけられない**ことがあるのです。巻き尺で測った距離と、表示された距離をくらべて、ちがう所がないか確かめましょう。

コースの準備として、次のことをしましょう。

1. ガラスの戸や窓、鏡、光る金属の板の、LIDAR の高さのところに、紙や養生テープを貼るか、段ボールでおおう
2. 黒い物（黒いカバンや、黒い布）は、コースのそばに置かない
3. `lidar_check.py` で、測れない点が多い向きや、巻き尺とちがう距離がないか確かめる
4. 走らせるときは、いつでも RB をはなせるように、車を見ている（9-1）

## ④ 数式・コード

### 角度から番号を求める

点の数を $n$ とすると、角度 $\theta$（度）の点の番号 $i$ は、次のとおりです。

$$
i = \operatorname{round}\left(\theta \times \frac{n}{360}\right)
$$

$n = 720$ なら 90° は 180 番、$n = 1080$ なら 90° は 270 番です。`racecar_utils` の関数も、この計算をしています。

### 鏡に映った物までの距離

鏡まで $a$ cm、鏡から映っている物まで $b$ cm のとき、LIDAR が測る距離は $a + b$ cm です。光は、鏡ではね返ってから、映っている物まで行って、同じ道をもどってくるからです。LIDAR は、光がまっすぐ進んだと考えるので、鏡の向こう $b$ cm のところに物があるように見えます。

## ⑤ つまずきポイント

### シミュレータでは正しく動いたのに、実機で壁に寄っていく

`scan[180]` や `scan[540]` のように、番号で右や左の距離を読んでいないか確かめましょう。`rc_utils.get_lidar_average_distance(scan, 90)` のように角度で書くか、`len(scan)` から番号を計算します。

### `ValueError: operands could not be broadcast together` が出る

720 個の角度の配列を、ファイルのはじめに作っていないか確かめましょう。`lidar_angles(scan)` のように、受けとった `scan` から、そのつど角度を作ります。

### 窓の近くで、車が急に曲がる・止まらない

窓ガラスや、ガラスの戸が、「空いている」と見えている可能性があります。`lidar_check.py` と巻き尺で確かめ、テープや段ボールでおおいましょう。

## ⑥ 確認問題

**問1**　実機の LIDAR（1080 点）で、左（270°）の距離の番号は何番ですか。シミュレータ（720 点）では何番ですか。

:::details 答え
実機は $270 \times 1080 / 360 = 810$ 番、シミュレータは $270 \times 720 / 360 = 540$ 番です。
:::

**問2**　実機で `scan[90]` と書くと、何度の向きの距離になりますか。

:::details 答え
$90 \times 360 / 1080 = 30$ 度（右ななめ前）です。シミュレータなら 45 度です。
:::

**問3**　正面 100 cm のところに鏡があり、鏡に映っている壁は、鏡から 150 cm のところにあります。LIDAR の正面の距離は、何 cm になりますか。

:::details 答え
$100 + 150 = 250$ cm です。鏡があるのに、250 cm 先まで何もないように見えます。
:::

## ⑦ 原典

- 実機の LIDAR が約 1080 点を返すこと、m から cm へ直すこと、並ぶ向きを時計回りにそろえること、無限大を 0 にすること、`get_num_samples()` を使うようにという注意：[racecar-neo-library](https://github.com/MITRacecarNeo/racecar-neo-library) の `real/lidar_real.py`（GPL-3.0）
- `get_lidar_average_distance()`・`get_lidar_closest_point()` が `len(scan)` から番号を計算すること：同じく `racecar_utils.py`
- 実機の LIDAR（RPLIDAR）の設定：[racecar_neo_ros2_driver](https://github.com/MITRacecarNeo/racecar_neo_ros2_driver) の `config/lidar.yaml`

`lidar_check.py`・表・図1の中と右・表示の例は、この本で作った説明用の簡単なモデル（上から見た2次元の車と壁、1080 点・1 秒に 10 回転の LIDAR、LIDAR に見えないガラス）によるものです。実際の LIDAR が、ガラスや鏡、黒い物をどう測るかは、物の材質や角度で変わります。
