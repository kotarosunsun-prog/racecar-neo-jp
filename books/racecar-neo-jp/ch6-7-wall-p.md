6-5・6-6 で、右の壁までの距離を安定して測れるようになりました。この回では、いよいよハンドルを動かします。6-1 の比例制御（P 制御）を使って、壁から決まった距離を保って走るプログラムを書きます。

## ① この回でできるようになること

1. 壁沿い走行の「ずれ」を決めて、ずれの符号とハンドルの向きを対応させられる
2. ずれに比例してハンドルを切る、P 制御の壁沿い走行プログラムを書ける
3. KP の大きさや速さで、走り方がどう変わるかを説明できる

## ② 使う用語

| 英語 | 日本語 | ひとことで言うと |
|---|---|---|
| Error | ずれ（誤差） | 測った値 − 目標の値 |
| Proportional control (P) | 比例制御（P 制御） | ずれに比例した強さで、命令を決める方法（6-1） |
| Gain | ゲイン | ずれを何倍して命令にするか。P 制御では KP |
| Oscillation | 振動（ふらつき） | 目標のまわりを、行ったり来たりすること |

## ③ 本文

### ずれの符号と、ハンドルの向き

目標は、右の壁から `TARGET = 50` cm の所を走ることです。ずれを次のように決めます。

$$
\text{error} = \text{distance} - \text{TARGET}
$$

| 状態 | ずれ | どちらにハンドルを切るか | angle |
|---|---|---|---|
| 壁から遠すぎる（例：70 cm） | ＋（+20） | 右（壁のほう） | ＋ |
| ちょうどよい（50 cm） | 0 | まっすぐ | 0 |
| 壁に近すぎる（例：30 cm） | －（−20） | 左（壁から離れる） | － |

RACECAR では、angle が＋なら右、－なら左に曲がります。ずれが＋のとき右に切ればよいので、ずれと angle は**同じ符号**です。そこで、6-1 と同じく、ずれに KP をかけたものを angle にします。

$$
\text{angle} = K_P \times \text{error}
$$

### KP の最初の決め方

6-1 で学んだように、「ずれがいくつのとき、ハンドルをいっぱい（angle = 1）に切りたいか」から、KP の最初の値を決めます。ここでは「50 cm ずれたら、いっぱいに切る」ことにして、

$$
K_P = \frac{1}{50} = 0.02
$$

とします。ずれが 50 cm より大きいときは、`clamp()` で angle を −1〜1 におさえます。

### やってみよう：P 制御で壁にそって走る

6-6 の `right_wall_distance()` を使って、右の壁にそって走るプログラムを書きます。壁が見えないとき（`None`）は、まっすぐ走ることにします。

```python:wall_follow_p.py
"""
wall_follow_p.py
右の壁から TARGET cm の距離を保って走る（比例制御：P）。
"""

import sys

sys.path.insert(1, "../../library")
import racecar_core
import racecar_utils as rc_utils

rc = racecar_core.create_racecar()

TARGET = 50.0     # 右の壁から保ちたい距離（cm）
SPEED = 0.3       # 走る速さ（一定）
KP = 0.02         # 比例ゲイン：50 cm ずれたら、ハンドルをいっぱいに切る
MAX_WALL = 300.0  # これより遠いときは「壁なし」とみなす

distance = None   # 右の壁までの距離（update_slow で表示する）
angle = 0.0


def right_wall_distance(scan):
    """右の壁までの距離（cm）。壁が見つからなければ None（6-6）"""
    closest_angle, closest = rc_utils.get_lidar_closest_point(scan, (45, 135))
    if closest > MAX_WALL:
        return None
    center = round(closest_angle * len(scan) / 360)
    near = []
    for d in scan[center - 10 : center + 11]:
        if 0 < d < closest + 5:
            near.append(d)
    return sum(near) / len(near)


def start():
    rc.drive.stop()
    print(f">> 右の壁から {TARGET:.0f} cm を保って走ります（P 制御、KP = {KP}）")


def update():
    global distance, angle

    scan = rc.lidar.get_samples()
    distance = right_wall_distance(scan)

    if distance is None:
        angle = 0.0                                     # 壁が見えないときは、まっすぐ
    else:
        error = distance - TARGET                       # ＋：壁から遠すぎる、－：近すぎる
        angle = rc_utils.clamp(KP * error, -1.0, 1.0)   # ずれに比例してハンドルを切る

    rc.drive.set_speed_angle(SPEED, angle)


def update_slow():
    if distance is None:
        print("壁が見えない")
    else:
        print(f"右の壁まで {distance:5.1f} cm　ずれ {distance - TARGET:+5.1f} cm　angle {angle:+.2f}")


if __name__ == "__main__":
    rc.set_start_update(start, update, update_slow)
    rc.go()
```

### KP をかえてみる

![説明用の簡単なモデルで、P 制御だけで壁沿いに走らせた道すじ。横は進んだ距離（0〜700 cm）、たては右の壁までの距離。どれも壁から 70 cm の所からスタートし、目標の 50 cm の線をこえて、壁に近づいたり離れたりしながら進む。KP = 0.01（青）は、ゆっくり大きく揺れて、27〜75 cm の間を行き来する。KP = 0.02（オレンジ）は、もう少し速く揺れ、揺れがだんだん大きくなって、最後は 17 cm まで壁に近づく。KP = 0.04（紫）は、速く大きく揺れて、400 cm ほど進んだ所で壁にぶつかる](/images/racecar-neo-jp/6-7/fig1-paths.png)
*図1　P 制御だけで壁沿いに走った道すじ（speed 0.3、15 秒、説明用の簡単なモデル。たての目もりを横より2倍以上広げて描いている）*

- **KP = 0.01**：ゆっくり、大きく揺れる。目標に近づくのに時間がかかる
- **KP = 0.02**：もう少し速く揺れる。揺れはだんだん大きくなる
- **KP = 0.04**：速く揺れ、揺れがすぐに大きくなって、10秒ほどで壁にぶつかった

6-1 の「壁の手前で止まる」では、KP を調整すれば、行き過ぎても、やがて目標で止まりました。ところが壁沿い走行では、**どの KP でも揺れが止まりません**。KP を小さくしても、揺れがゆっくりになるだけです。

速さを上げると、もっと悪くなります。モデルで KP = 0.02 のまま speed を 0.5 にすると、揺れが速く大きくなり、8秒ほどで壁にぶつかりました。

シミュレータでも、Lab I のレベルで、KP と SPEED を変えて走らせてみましょう。ゆっくりなら、しばらくは壁にそって走れるはずです。でも、揺れが止まらないことにも気づくでしょう。なぜ揺れが止まらないのか、次の 6-8 で、記録をとって調べます。

## ④ 数式・コード

### KP の単位

ずれの単位は cm、angle には単位がありません（−1〜1）。KP は「1 cm ずれたら、angle をいくつにするか」なので、単位は「1/cm」です。`KP = 0.02` は、「1 cm ずれるごとに angle を 0.02 ずつ増やす」という意味です。

| ずれ（cm） | −60 | −25 | −10 | 0 | +10 | +25 | +60 |
|---|---|---|---|---|---|---|---|
| KP × ずれ | −1.2 | −0.5 | −0.2 | 0 | +0.2 | +0.5 | +1.2 |
| angle（clamp のあと） | −1.0 | −0.5 | −0.2 | 0 | +0.2 | +0.5 | +1.0 |

### 左の壁にそって走るとき

左の壁の場合は、ずれが＋（壁から遠すぎる）のとき、**左**（angle が－）に切ります。符号が反対になるので、KP の前に「－」をつけます。窓も左側 `(225, 315)` に変えます。

```python
error = left_distance - TARGET                     # ＋：左の壁から遠すぎる
angle = rc_utils.clamp(-KP * error, -1.0, 1.0)     # 遠すぎたら左（－）へ
```

## ⑤ つまずきポイント

### 壁からどんどん離れていく（または、まっすぐ壁に突っこむ）

ずれと angle の符号が逆になっています。右の壁なのに `-KP * error` と書いたり、左の壁なのに `KP * error` と書いたりすると、「遠すぎるのに、もっと離れる」向きにハンドルを切ってしまいます。表示される「ずれ」と「angle」の符号が、③の表のとおりになっているか確かめましょう。

### 走り出したとたんに、大きくハンドルを切る

スタートの位置が目標から遠いと、はじめのずれが大きくなり、ハンドルをいっぱいに切ります。そのまま壁の近くまで行くと、行き過ぎて壁にぶつかることがあります。はじめは、目標の距離の近くからスタートしてみましょう。6-9 で、この行き過ぎをおさえる方法を学びます。

### 揺れが止まらない

P 制御だけでは、揺れは止まりません。KP を小さくしても、ゆっくり揺れるだけです。理由は 6-8 で、対策は 6-9・6-10 で学びます。

## ⑥ 確認問題

**問1**　右の壁から 62 cm の所を走っています。`TARGET = 50`、`KP = 0.02` のとき、angle はいくつですか。車はどちらに曲がりますか。

:::details 答え
ずれは $62 - 50 = 12$ cm、angle は $0.02 \times 12 = 0.24$ です。＋なので右（壁のほう）に曲がります。
:::

**問2**　「30 cm ずれたら、ハンドルをいっぱいに切る」ようにしたいとき、KP はいくつにしますか。

:::details 答え
$1 \div 30 \approx 0.033$ です。
:::

**問3**　左の壁にそって走るプログラムで、左の壁まで 40 cm、`TARGET = 50`、`KP = 0.02` のとき、angle はいくつですか。

:::details 答え
ずれは $40 - 50 = -10$ cm です。左の壁なので angle は $-0.02 \times (-10) = +0.2$ で、右（左の壁から離れる向き）に曲がります。
:::
